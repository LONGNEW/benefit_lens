# BenefitLens 웹

현재 PostgreSQL 데모의 기본 실행은 루트의 `make demo`다. 아래 문서는 별도 Next/Vinext와 D1 앱의 개발 기록이며 DB 복원만으로 D1이 갱신되지는 않는다. [저장 구조](../docs/DATA_LAYOUT.md)에서 두 경로를 구분한다.

공식 원천에서 수집한 지원 기회를 검색하고, 사용자가 브라우저에 입력한 조건과 비교한 뒤, 선택한 기회와 확인된 경험을 연결해 첫 초안을 만드는 Vinext 기반 프로토타입이다. 루트 경로는 `/benefitlens`로 이동하며, 조회 API는 `/api/opportunities`에서 제공한다.

## 로컬 실행

Node.js 22.13 이상이 필요하다.

```bash
npm ci
npm run dev
```

검증 명령은 다음과 같다.

```bash
npm run lint
npm run build
npm test
```

## 데이터 흐름

1. 백엔드 파이프라인이 PostgreSQL에 공식 원본과 정규화 후보를 저장하고 공고 버전별 금전 지원의 복수 분류와 근거 문구를 저장한다.
2. `scripts/sync_d1.py`가 검토 후보를 이 앱의 D1 스테이징 테이블로 보낸다.
3. `/api/admin/sync`가 토큰을 확인하고 건수를 검증한 뒤 조회 테이블을 교체한다.
4. `/api/opportunities`가 D1을 읽고, 연결할 수 없으면 검증용 고정 예시를 반환한다. 기본값 `fundingTarget=financial`은 현금성 지원, 장학금, 등록금과 생활비 중 하나 이상인 후보를 조회한다. `cash`, `scholarship`, `tuition`, `living_expenses`로 각각 조회하고 `all`로 비금전 후보를 포함한 전체 보관 목록을 조회한다. `operatorGroup`은 실제 등록된 운영기관 유형이며 학교 수집 경로와 별개다.
5. `/benefitlens` 화면은 전체 검색 결과를 읽은 뒤 브라우저에서 개인 조건을 비교하고 페이지를 나눈다. 개인정보는 조회 요청에 보내지 않는다.
   초기 입력은 소속, 학위 과정과 학적 상태의 선택 항목 3개다. 입력 없이도 모든 후보를 탐색할 수 있고 저장한 값은 재사용한다. POSTECH 학과를 명시적으로 고르면 공식 학과 목록에 따라 학교 소속을 연결한다. 공고를 고르면 해당 자격 트리에서 아직 모르는 정보만 질문한다. OR 경로가 이미 통과했으면 다른 경로를 묻지 않고, 미확인 경로가 여러 개이면 필요한 질문 수가 적은 경로부터 제시한다. 소득, 성적, 국적이나 재직 여부는 공개 자료에서 추측하지 않는다.
6. 선택한 기회와 경험 입력은 브라우저 안의 결정적 기준선이 초안과 문장별 근거로 바꾼다.

동기화 토큰은 `D1_SYNC_TOKEN` 비밀값으로 주입하며 저장소에 넣지 않는다. Cloudflare D1 바인딩 이름은 `DB`다.

## 주요 경로

- `app/benefitlens/`: 화면과 조건 비교 UI
- `app/api/opportunities/`: 조회 API
- `app/api/admin/sync/`: D1 동기화 API
- `lib/opportunity-data.ts`: 연결 실패 시 사용하는 예시 데이터
- `app/benefitlens/draft-workbench.tsx`: 선택한 기회와 사용자 경험을 연결하는 브라우저 내 초안 기준선
- `db/schema.ts`: D1 스키마
- `drizzle/`: D1 마이그레이션

현재 화면의 후보는 자동 확정 결과가 아니다. 초안도 실제 공식 문항을 아직 연결하지 않은 기준선이다. 실제 신청 전 공식 원문, 최신 자격 조건과 문항 적합성을 다시 확인해야 한다.

조건 판정은 `eligibility-1.5.0`의 자료형, 단위와 연산자를 사용한다. AND, OR와 NOT을 3상태로 계산한다. `접수 가능`은 모든 필수 조건 통과와 현재 접수 기간 확인을 함께 요구한다. `제도 대상 가능`은 제도의 구조화된 대상 범위와 내 정보가 맞을 때만 표시한다. 다른 GPA 만점은 임의 비례 환산하지 않는다.

카드의 지원 자격은 표준 기준 레이블로 요약한다. 미해석 원문과 판정 트리는 `전체 조건과 판정 근거`에서 보여준다. 초기 프로필은 비어 있으며 예시 데이터를 실제 접수 판정에 사용하지 않는다. `public/school-coverage.json`은 학교 전체 탐색에서 확인한 범위와 미수집 경로를 공개한다.
