# 개인화 명세의 합성 계약 예시

이 폴더는 미래 입출력 계약을 검토하기 위한 자료다. 공고, 사람, 프로필과 지원서 구절은 모두 합성이며 example.org URL은 실제 수집 주소가 아니다. 현재 제품에 신규 검색이나 업로드 API를 연결하지 않았다.

합성 자료는 quote를 합성 문서의 전체 본문으로 정의하고 그 SHA256을 content_sha256에 기록했다. 실제 원문을 내려받은 해시가 아니다. 제품 구현에서는 보관한 실제 원문 전체의 해시를 사용한다.

## 구성

- [합성 계획](personalization-plan.synthetic.json): 요구, 개인 사실 후보, 서류 상태, 세 축 판정, 결과 미상 사례에서 얻은 지침과 초안 슬롯.
- [JSON Schema](../../docs/specs/personalization-plan.schema.json): 필수 필드와 상태, 추론 후보의 사용 차단, 선정 원인 주장 금지.
- [검사기](validate_contract.py): ID 교차 참조, 주체와 자료 역할, 적용 시점, 작성 슬롯의 사실 사용 등 선언된 계약 규칙.
- [검사 결과](contract_validation.json): 정상 예시 1개와 잘못된 예시 14개에 대한 결과.

합성 예시에서 F-topic은 동일인 연결도 모호한 공개 프로필의 해석 후보다. 초안과 확정 판정에는 쓰지 않는다. F-action은 합성 사용자가 확인한 본인 행동이며, 결과 수치가 없어 초안에 빈칸과 추가 질문을 남긴다.

참고 사례의 결과는 unknown이어도 원문 발췌와 현재 문항을 대조한 avoid 지침을 만들 수 있다. 관찰은 공개 발췌에 한정하며 선정이나 탈락 원인으로 쓰지 않는다.

## 다시 검사하기

저장소 루트에서 실행한다.

```bash
.venv/bin/python evaluation/spec_examples/validate_contract.py
```

검사는 파일을 읽고 JSON 결과를 표준출력으로 내보낸다. 웹 검색, 모델 호출과 DB 쓰기는 하지 않는다.

JSON Schema만으로 원문 진실성, 동일인 판단이나 인용의 뒷받침을 검증할 수는 없다. 이 검사기는 이미 선언된 주체와 상태의 일관성을 확인한다. 실제 자료의 의미 정확도와 사용자 효과는 [평가 규약](../../proposal/07_평가_계획과_채점_기준.md)의 독립 주석으로 검증한다.

현재 HTTP 응답과 DB를 이 계약으로 바꾸는 어댑터, 실제 공개 검색과 개인 문서 처리, 서류 확보와 초안 생성 경로는 후속 구현이다.
