# BenefitLens 시스템 파이프라인 명세

## 프로젝트 개요

학생은 여러 기관의 모집 공고를 찾아 자격을 확인하고, 지원서를 쓸 때마다 다른 사람의 경험을 다시 검색한다. BenefitLens는 공고를 공통 조건으로 정리해 학생 정보와 비교하고, 선택한 프로그램의 실제 경험에서 작성 패턴을 연결한다.

첫 출력은 조건에 맞는 기회와 혜택이다. 다음 출력은 공식 문항과 경험 패턴을 반영한 작성 개요다. 사용자 사실을 받아 완성 지원서를 생성하는 연결은 후속 구현이다.

발표 순서는 미술 사례의 원문 목차인 “프로젝트 개요”, “시스템 아키텍처”, “데이터 엔지니어링 구현”, “핵심 추론 엔진”, “서비스 시연 및 결과”, “결론 및 향후과제”를 따른다. 출처는 [미술 큐레이팅 발표 추출문](</home/longnew/Desktop/course_work/tmp/unlock-presentation-plan-20260914/extracted/04_art_curation.txt>) 2쪽이다.

## 시스템 아키텍처

```text
오프라인 처리
공식 공고, 양식, 공개 경험
  → 수집과 원본 보존 → 텍스트 추출, 필요 시 OCR
  → 공고: 조건 트리, 혜택, 문항
  → 경험: 사례 분석, 작성 패턴, 필요한 사용자 사실
  → 근거 검사 → PostgreSQL 적재와 변경 이력

온라인 처리
학생 기본정보 → 기본 조건 비교 → 공고와 혜택
  → 공고 선택 → 추가 자격, 제출 및 활동 요구사항
  → program_id로 경험 연결 → 패턴과 빈칸 개요
  → 사용자 사실 입력과 문장 생성 [후속 구현]
```

| 미술 사례의 역할 | BenefitLens의 대응 |
|---|---|
| MET CSV와 API, 작가 정보 | 공식 공고와 양식, 프로그램별 공개 경험 |
| 작품, 작가, 사조 관계 | 기관, 프로그램, 회차, 경험 사례 관계 |
| 이미지 설명과 온톨로지 전처리 | 원문에서 조건과 혜택, 경험에서 문단 역할과 패턴 추출 |
| SPARQL과 벡터 기반 작품 검색 | SQL 조회와 코드 기반 조건 판정, 프로그램 지식 조인 |
| 추천 이유와 관람 동선 | 자격 판정 근거와 혜택, 제출 준비 순서와 작성 개요 |

기본 자격은 수치와 논리 연산이므로 조건 트리로 비교한다. 프로그램과 사례 연결은 ID 조인으로 충분하다. 현재 데모에는 별도 그래프 DB나 벡터 DB를 추가하지 않는다.

## 핵심 추론 엔진

조건은 `(필드, 연산, 값)`을 잎으로 갖고 `all`, `any`, `not`으로 연결한다. 예를 들어 관정 학부 예제는 학위, 국적, 만점별 GPA 분기를 모두 비교한다. GPA는 원문에 있는 `4.0/4.5`와 `3.8/4.3` 분기를 보존한다. 없는 만점의 공식 환산식은 만들지 않는다.

조건 판정은 일치, 불일치, 정보 부족을 반환한다. 기본 조건, 추가 자격, 모집 기간, 제출 및 활동 요구사항을 따로 표시한다. NVIDIA 박사 첫 학년 미완료는 예외 심사 경로로 남기며, 인턴십 수행은 신청 후 요구사항으로 보여준다.

경험은 `program_id`로 공고에 연결한다. 사례의 과거 회차와 현재 모집 회차를 함께 보존하고, 선정 또는 미선정 결과와 실제 제출본 확인 수준을 구분한다. 패턴은 타인의 사실이 아니라 문단 역할과 사용자에게 필요한 사실 목록을 제공한다.

## 서비스 시연 및 결과

다음 한 명령이 원문 검사부터 웹 판정까지 실행한다. PostgreSQL 예제 DB, Node와 기존 비공개 원문이 필요하다.

```bash
make pipeline-replay
```

수집과 모델 호출을 새로 하지 않는 `snapshot replay`다. 실행기는 저장 원본에서 텍스트를 다시 추출하고 해시와 인용, 스키마를 검사한다. DB에 두 번 적재한 뒤 임시 HTTP 서버를 통해 웹과 같은 조건 판정 함수를 실행한다. 실패하면 성공 기록을 교체하지 않고 `.local/pipeline-replay/last-failure.json`에 원인을 남긴다.

2026년 10월 18일 실행 결과는 공고 10개, 조건 트리 9개와 세부 조건 36개, 경험 문서 25개, 사례 14개, 패턴 17개다. 공고 4개와 경험 25개의 원본에서 HTML 17개와 PDF 12개의 텍스트를 다시 추출해 보관본과 일치함을 확인했다. 이번 입력에는 OCR 대상이 없었다. 기본 프로필 비교는 3개 일치, 6개 불일치, 1개 미확인이며 11개 경계 및 예외 시나리오가 통과했다. 같은 DB 적재를 반복해 변경 이력 30개가 유지됐다.

화면은 `/assets/pipeline-run.html`, 기계 판독 결과는 `/assets/pipeline-run.json`이다. 실행 결과에서 각 공고의 상세 데모로 이동한다.
