# 공고의 자격 조건과 혜택을 정리하는 전처리와 스키마

## 목적과 우선 범위

첫 기능은 학생이 어떤 혜택을 받을 수 있고 어떤 기회에 신청할 기본 조건을 갖췄는지 보여주는 것이다. 서로 다른 공고를 같은 필드로 표현하고, 학생의 정보를 해당 공고의 조건에 대조한다.

발표의 핵심은 자격 조건과 혜택이다. 접수 기간, 신청 URL과 작성 문항은 연결 정보로 보존하고 특약의 상세 분석은 후속 범위로 둔다. 원문에 명시된 신청 불가 조건은 자격에 포함하며 제출할 서류와 선정 후 활동은 별도 안내로 둔다.

기준일은 2026년 10월 15일이다. 공통 구조를 데모 DB에 적용했고, 아래 가상 예시와 실제 적재 결과를 구분한다.

## 원문을 구조화하는 순서와 LLM의 역할

1. HTML, PDF와 한글 문서에서 텍스트를 추출한다. 텍스트가 없는 페이지와 이미지에는 OCR을 적용하고 원본 위치를 유지한다. 표의 연결이나 그림의 의미가 텍스트에 남지 않으면 해당 구역을 멀티모달 LLM으로 읽는다.
2. 같은 사업과 회차의 본문, 첨부와 추가 공지를 연결한다.
3. LLM이 원문을 읽어 자격과 혜택을 설명하고, 비교할 조건을 `항목, 연산자, 값`으로 분해한다. 조건의 적용 시점, 예외와 원문 근거를 함께 붙인다.
4. 공통 자료구조로 직렬화한 뒤 필드, 자료형, 단위, AND와 OR 연결 및 근거 위치를 검사한다. 단순 변환 실패는 코드를 수정하고 의미가 빠지거나 연결이 틀리면 해당 근거를 LLM에 다시 제공한다.
5. 사용자 비교에는 정규화된 규칙을 사용한다. 매번 LLM에 개인 정보를 보내 자격을 다시 판단하게 하지 않는다.

추출 대상은 문장 내부의 연결이다. 예를 들어 GPA, 이상, 3.5와 만점을 하나의 조건으로 결합하고, 예외나 대안이 어디에 연결되는지 표현한다. 표와 다른 문서에 있는 기준도 같은 조건의 근거에 연결한다.

전처리 한 건은 연결 원문을 확보하고 자격 및 혜택 구절을 기본 조건, 추가 자격과 안내에 배치한 뒤 마친다. 근거가 없는 값과 미연결 예외는 재처리 대상으로 둔다. 초기에는 수정 추출을 최대 두 번 시도하고 남은 항목은 `partial`로 기록한다. 원문에서 조건을 놓쳤는지는 별도의 원문 대조로 확인한다.

실제 NVIDIA, 관정과 Google 공식 페이지에서 HTML 텍스트와 조건 구절을 확보했다. [Rohan의 제안서 PDF](https://rohany.github.io/reports/nvidia-fellowship-proposal.pdf)도 두 페이지의 글자가 추출된다. 따라서 이 예시에는 텍스트 우선 경로를 쓸 수 있다. 전체 원장의 이미지 전용 자료 비율은 아직 집계하지 않았으므로 OCR 분기는 유지한다.

## 자연어와 조건 표현 및 JSON의 차이

사람에게는 “학부 1~3학기 성적이 기준 이상” 같은 설명을 보여준다. 프로그램에는 `(GPA, 이상, 4.0)`에 만점 4.5, 학위와 산정 기간을 붙여 비교하게 한다. 여러 조건의 AND와 OR는 별도로 연결한다. 자연어만 저장하면 조회할 때 같은 문장을 다시 해석해야 한다.

JSON은 이 구조를 주고받고 저장하는 형식이다. 100개 공고마다 별도 양식을 만드는 대신 공통 필드와 연산자를 재사용한다. 자연어 설명과 구조화된 조건을 함께 보존한다. 직접 구조 출력이 불안정하면 문장과 근거를 먼저 추출한 뒤 별도 단계에서 조건을 정규화한다.

## 공고 한 건의 공통 구조

사용자가 보는 공고 한 건은 `기관 + 사업 + 모집 회차`에 대응한다. 동일 회차의 정정문과 첨부는 이 객체의 원문 묶음이다. 사업에 공통인 경험 사례와 작성 패턴은 `program_id`로 연결한다.

| 필드 | 자료형과 값 | 역할 |
|---|---|---|
| `opportunity_id`, `program_id`, `round_id` | 문자열 | 공고, 사업과 회차 식별 |
| `title`, `issuer`, `source_refs` | 문자열, 객체와 배열 | 이름, 제공 주체와 원문 근거 |
| `category` | scholarship, fellowship, internship, admission_funding, competition, living_support, research_grant, other | 대표 기회 종류 |
| `recipient_type` | individual 또는 organization | 지원 대상 단위 |
| `eligibility` | 중첩 객체와 배열 | 기본정보로 비교할 조건 |
| `additional_checks[]` | 질문 객체 배열 | 특정 공고에만 필요한 추가 자격 확인 |
| `benefits` | 혜택 객체 배열 | 현금, 등록금, 생활비, 연구비와 경험 기회 |
| `application` | 객체 | 기간, URL, 공식 문항과 제출 분량 |
| `requirements[]`, `explanation` | 안내 배열, 문자열 | 제출 및 활동 요구사항, 읽기 쉬운 설명 |
| `extraction_status` | unprocessed, partial, reviewed_demo | 대기, 부분 추출과 원문을 읽어 정리한 데모 |

`issuer`는 `id, name, type, country`를 가진다. `type`은 government, company, foundation, university 등으로 나눈다. 국가 장학금과 대학원 장학금은 다른 대표 종류를 계속 추가하는 대신 `category=scholarship`, 제공 주체와 대상 학위의 조합으로 조회한다.

`category`는 장학금이나 인턴십 같은 프로그램의 대표 형태다. `benefits`는 등록금, 현금과 멘토링처럼 실제 제공 내용을 담는다. 태그는 이 둘과 중복되므로 필수 스키마에서 뺀다.

LLM이 새 조건을 발견하면 아래 사전 또는 공고별 추가 질문에 대응시킨다. 새 공통 의미가 필요하면 근거와 함께 필드 추가 대상으로 남긴다. 원문에서 조건을 찾지 못한 상태와 명시적으로 제한이 없는 상태를 구분한다.

## 자격 조건의 필드 사전

| 필드 | 자료형과 허용 표현 | 구분해야 할 의미 |
|---|---|---|
| `person.nationalities` | 국가 코드 배열 | 한국 국적과 이중국적 제외 |
| `person.birth_date` | 날짜 | 기준일의 연령 또는 출생일 경계 |
| `residence.country`, `residence.region` | 국가와 행정구역 코드 | 현재 거주 조건 |
| `education.institution_id`, `education.country` | 기관 ID와 국가 코드 | 재학 대학과 소속 국가 |
| `education.degree`, `education.status` | bachelors, masters, phd와 enrolled, incoming, graduated | 학위 과정과 재학 또는 진학 상태 |
| `education.major_group`, `education.major_raw` | 통제 분류와 원문 전공명 | 전공 묶음과 원문 표현 |
| `education.semester`, `education.full_time` | 정수와 불리언 | 학기와 전일제 |
| `education.gpa` | 숫자와 척도 | 학위, 성적 산정 기간과 만점 |
| `finance.income_quantile`, `employment.status` | 정수와 통제 분류 | 소득 구간과 취업 상태 |

이 표는 자주 쓰는 필드 사전이며 가입 시 전부 입력받는 항목이 아니다. 현재 확인된 국적, POSTECH, 박사과정 1학기, 전일제와 미취업을 먼저 사용하고 후보 비교에 필요한 값만 요청한다. 출생 연도만 있으면 생일 경계의 연령 판정에는 추가 확인이 필요하다.

필드마다 허용 연산자와 단위를 고정한다. 국가와 학위는 `eq`, `in`, `not_in`, 숫자와 날짜는 `gte`, `lte`, `between`, 불리언은 `eq`를 사용한다. `at`은 application, award_start, award_period로 구분하고 필요한 기준일을 붙인다. 원문과 정규화 값은 함께 보존한다.

## 특정 공고에서만 필요한 추가 질문

박사 첫 학년 완료, 박사 교과 대부분 이수, 고교 출신 국가, 편입 여부와 중복 수혜는 각 공고의 `additional_checks[]`로 둔다. 각 항목은 `check_id, question, answer_type, accepted_when, at, evidence_ref, exception`을 가진다. 답변은 `opportunity_id + check_id`에 연결하고 전역 프로필에 임의의 새 필드를 만들지 않는다.

`answer_type`은 예 또는 아니오, 선택값, 숫자나 날짜이고 `accepted_when`은 답변에 적용할 연산자와 기준값이다. 예외 승인이 필요한 항목은 기관 판단 필요로 표시한다.

예를 들어 NVIDIA에는 첫 학년을 마쳤는지와 연구 이력에 따른 예외 경로를, Google 동아시아에는 수혜 시작 시점의 교과 이수 상태를 묻는다. 의미가 다른 두 조건을 현재 학기 하나로 자동 판정하지 않는다. 같은 의미가 여러 프로그램에서 반복되면 공통 필드로 승격을 검토한다.

추가 자격 조건이 명확히 불일치하면 신청 불가로 반영한다. 제출 서류와 참여 활동은 `requirements[]`에 안내한다. 사용자가 아직 답하지 않은 추가 자격 조건은 기본 조건 일치 카드에 확인 항목으로 표시한다.

## 조건 트리의 구체적인 예시

다음은 가상 공고의 구조 예시다. 한국 국적, 박사 재학과 석사 GPA 기준을 AND로 묶고 GPA의 척도별 대안은 OR로 묶었다.

```json
{
  "schema_version": "proposal-1",
  "opportunity_id": "example-2026",
  "program_id": "example",
  "round_id": "2026",
  "record_status": "design_example",
  "category": "scholarship",
  "recipient_type": "individual",
  "eligibility": {
    "all": [
      {"field": "person.nationalities", "op": "in", "value": ["KR"], "at": "application", "evidence_ref": "E1"},
      {"field": "education.degree", "op": "eq", "value": "phd", "at": "application", "evidence_ref": "E1"},
      {"field": "education.status", "op": "eq", "value": "enrolled", "at": "application", "evidence_ref": "E1"},
      {"any": [
        {"field": "education.gpa", "op": "gte", "value": 3.5, "scale": 4.5, "degree_scope": "masters", "period_scope": "cumulative", "at": "application", "evidence_ref": "E2"},
        {"field": "education.gpa", "op": "gte", "value": 3.3, "scale": 4.3, "degree_scope": "masters", "period_scope": "cumulative", "at": "application", "evidence_ref": "E2"}
      ]}
    ]
  },
  "benefits": [
    {"type": "living_allowance", "amount": 1000000, "currency": "KRW", "period": "semester", "amount_kind": "fixed", "evidence_ref": "E3"}
  ],
  "source_refs": [
    {"id": "E1", "document_id": "example-raw", "locator": "가상 자격 문장 1", "quote": "한국 국적 박사과정 재학생"},
    {"id": "E2", "document_id": "example-raw", "locator": "가상 자격 문장 2", "quote": "석사 누적 GPA 3.5/4.5 또는 3.3/4.3 이상"},
    {"id": "E3", "document_id": "example-raw", "locator": "가상 혜택 문장", "quote": "생활비 학기당 100만원"}
  ]
}
```

여기서 트리는 별도 SQL 자료형이 아니라 `all` 안에 조건과 `any`가 들어가는 중첩 구조를 뜻한다. 프로그램에서는 객체와 배열로 읽고 PostgreSQL에는 JSONB로 저장하는 안이다. `all`은 AND, `any`는 OR, `not`은 제외 조건이다. 말단 조건은 `field, op, value, at, evidence_ref`를 가지며 GPA에는 `scale, degree_scope, period_scope`가 필요하다.

`in`에서 사용자 값이 배열이면 기준 집합과 하나 이상 겹치는지 비교하고 `not_in`은 겹치지 않는지 비교한다. GPA는 사용자의 만점에 해당하는 원문 분기를 적용한다. 값이나 산정 기간이 없거나 해당 척도의 기준이 없으면 필요한 정보를 요청한다.

위 GPA 값은 구조를 설명하기 위한 가상 기준이다. 실제 공고의 4.3과 4.5 기준을 각각 추출해 적용한다. 표시용 비율과 자격 기준은 분리하며 다른 척도를 임의 환산해 같은 컷으로 만들지 않는다.

## 혜택의 필드와 사용자 매칭

혜택에는 `type`, `amount`, `currency`, `period`, `amount_kind`와 `evidence_ref`를 둔다. 종류는 tuition, living_allowance, research_fund, cash, internship, mentoring, travel 등으로 구분하고 금액은 fixed, maximum, range로 표시한다. range는 `min_amount`와 `max_amount`를 사용한다. 명시되지 않은 금액은 `null`이다. 인턴십이라는 이름만 보고 급여가 있다고 추정하지 않는다.

AND에서 하나가 불일치하면 다른 값이 비어 있어도 기본 조건 불일치다. 모두 일치하면 기본 조건 일치, 나머지는 기본정보 추가 필요다. OR는 하나가 일치하면 일치한다. 박사에게 학부 전용 장학금의 GPA를 추가로 묻지 않는다.

온라인 조회는 `개인 대상 및 학위 등 기본 필터 → 조건 비교 → 혜택 선호와 접수 기간 → 결과 카드` 순서다. 카드에는 기본 조건 결과, 혜택, 모집 상태와 남은 추가 질문을 나눠 보인다. 현재 전일제가 수혜 기간에도 유지된다고 가정하지 않는다. 아직 전처리하지 않은 공고는 추출 대기 상태로 둔다.

## 세 원문의 조건 표현을 검토한 결과

이번 소규모 검토는 NVIDIA, 관정과 [Google 공식 안내](https://research.google/programs-and-events/phd-fellowship/)의 선택한 문장을 읽어 구조 예시를 만들고, 그 표현을 로컬 코드로 비교한 것이다. 세 HTML에서 조건 구절을 찾았고, 자료구조 저장과 복원 및 비교 분기 10개를 확인했다.

| 입력 조건 | 확인된 동작 |
|---|---|
| 관정 학부 기준과 박사 프로필 | 학위에서 제외하고 GPA를 묻지 않음 |
| 관정 4.0/4.5와 3.8/4.3 | 각 척도의 경계값과 경계 미만을 구분 |
| GPA가 없거나 척도와 산정 기간이 다름 | 임의 환산 없이 필요한 정보를 요청 |
| NVIDIA와 Google의 박사 조건 | 기본 일치 뒤에도 프로그램별 추가 조건과 모집 상태 유지 |

첫 근거 대조에서는 관정 HTML의 괄호 앞 공백 때문에 문자열 일치가 실패했다. 공백을 정규화하자 같은 조건 구절을 찾았다. 원본과 정규화 텍스트를 나눠 보존할 이유다. [검증 결과](</home/longnew/Desktop/course_work/tmp/benefitlens_extraction_review_20261015/verification.json>)는 조건 표현의 동작 확인이며, 무인 LLM의 전체 공고 추출 시험은 다음 단계다. 그 시험에서는 조건 누락과 예외 연결을 원문 옆에서 확인한 뒤 반복 추출 방식을 결정한다.

NVIDIA 원문의 “Complete your first year of PhD-level studies before applying.”는 박사 첫 학년을 마친 상태다. 첫 학기나 석사 졸업을 뜻하지 않는다. FAQ의 연구 이력이 충분한 예외를 함께 보존한다. 2027~2028 회차의 접수 마감은 2026년 10월 30일이다.

관정 원문에는 “4.0(4.5 만점기준)/3.8(4.3 만점기준)”이 있다. 학부 1~3학기 누적 GPA의 척도별 분기로 연결한다. 이 공고는 과거 2026 선발 사례로 시연하며 학부 페이지의 표에 대학원 금액이 보인다는 이유로 학부 자격을 박사에 적용하지 않는다. 자기소개서의 “스스로 작성 할 것” 안내도 보존한다.

Gates의 확인 원장은 2026/27 회차다. 새 회차의 기간과 문항은 새 공식 버전에 연결하며 국적 허용만으로 입학과 장학 선정을 확정하지 않는다.
