## 중간 발표의 네 문서와 현재 결과

- [수집할 정보와 방법](</home/longnew/Desktop/course_work/26-2 학기/데이터엔지니어링/benefitlens/proposal/중간발표/01_수집할_정보와_방법.md>): 실제 검색 표현, 사전 확장과 종료 조건, 검색 결과 처리와 모집 공고 집계.
- [공고 전처리와 스키마](</home/longnew/Desktop/course_work/26-2 학기/데이터엔지니어링/benefitlens/proposal/중간발표/02_공고_전처리와_스키마.md>): 기본 조건과 공고별 추가 질문, 자연어와 저장 구조, 소규모 비교 결과와 실제 공고 예시.
- [수기와 경험 전처리와 스키마](</home/longnew/Desktop/course_work/26-2 학기/데이터엔지니어링/benefitlens/proposal/중간발표/03_수기와_경험_전처리와_스키마.md>): 경험 검색의 반복과 종료, 텍스트와 그림의 처리, 프로그램별 작성 관점과 사용자 질문.
- [DB 갱신과 보존 삭제](</home/longnew/Desktop/course_work/26-2 학기/데이터엔지니어링/benefitlens/proposal/중간발표/04_DB_갱신과_보존_삭제.md>): 오프라인 갱신과 온라인 조회, 공고 및 작성 지식 저장, 적재 검증과 보존 설계.

중간 발표는 위 네 문서를 기준으로 준비한다. 각 문서 안에 설계, 해당 분야의 실행 결과, 원문 근거와 발표에서 보여줄 자료를 함께 기록한다. 별도 [10월 14일 통합 정리](</home/longnew/Desktop/course_work/26-2 학기/데이터엔지니어링/benefitlens/docs/2026-10-14_지원정보_수집결과와_해외_선정사례.md>)는 이전 기록으로 보존한다.

DB 스키마와 구현 계약을 논의할 때는 [내부 DB와 파이프라인 기틀 초안](09_내부_DB와_파이프라인_기틀_초안.md)을 함께 본다. 회의 이후 범위는 [회의 결론과 실행 계획](10_회의_결론_및_실행계획.md)을 우선한다.

## 문서 간 기준

- 통합 제안서는 현재 합의된 범위의 기준 문서다.
- 세부 문서는 각 설계 결정을 설명하고 구현 과정에서 갱신한다.
- 수치나 범위가 달라지면 통합 제안서와 관련 세부 문서를 같은 날 수정한다.
- 교수님 일정은 [공식 프로젝트 일정표](https://docs.google.com/spreadsheets/d/1oPqM5g4XYwU_PZ0DFld4QVmYYWPAdWa8m3Cyl2n_rwY/edit?gid=0#gid=0)에서 읽기 전용으로 확인한다.

## 현재 한 문장

> BenefitLens는 여러 기관에 흩어진 지원 기회를 공식 데이터로 수집하고 개인 조건으로 걸러, 사용자가 같은 경험을 기관별 요구에 맞춰 반복해서 재작성하는 비용을 줄이는 근거 기반 지원 준비 파이프라인이다.
