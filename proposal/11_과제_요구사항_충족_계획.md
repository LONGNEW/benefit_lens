# 과제 요구사항과 최종 증거
기준일: 2026-11-04. 공식 요구와 팀 내부 완료 기준, 현재 상태를 구분한다.

## 1. 공식 요구의 원문

[공식 강의자료](../../1_overview.pdf) 27쪽의 제안 범위는 “Ideation, data collection & preprocessing, DB management”다.

최종 범위는 다음과 같다.
> Develop a product that addresses a real-world problem
> using a large-scale DB (with potential LLM integration)

따라서 최종에는 실제 문제를 다루는 제품과 DB 사용, 데이터 규모를 보여줘야 한다. 교안의 이 페이지에는 최소 건수, 특정 DB 종류와 LLM 필수 사용, 보고서 파일 확장자나 발표 페이지 수가 없다. 별도 최종 공지는 확인 항목으로 남긴다.

## 2. 요구사항 추적표

| ID | 요구 | 현재 근거 | 남은 증거 | 종료 기준 |
| --- | --- | --- | --- | --- |
| R1 | 실제 문제와 제품 | 공고 비교, 추가 조건과 작성 개요 흐름 | 실제 학생이 몰랐던 관련 후보와 판단/준비 과제 결과 | 고정된 사용자 과제가 실제 DB와 출력으로 이어짐 |
| R2 | 수집과 전처리 | 공고 4개와 경험 25개 원문 재처리 기록, 형식 계약 | 요약 6개 원문, Gates 조건, 신규 추출과 의미 정답 평가 | 원문, 고정 출력과 오류표를 함께 제시 |
| R3 | DB 관리 | PostgreSQL, program_id 조인, 반복 적재 불변의 과거 기록 | 현재 조회 복구, 변경과 실패 처리, 규모별 질의 | 실제 스키마와 연결 질의, 중복/버전 검사 재현 |
| R4 | large-scale DB 사용 | 현재 활성 예제 10개. 과거 수집은 별도 보관 | 교수자 인정 범위, 실제 고유 사업/회차/문서 집계, 용량과 질의 성능 | 인정 범위에 맞는 실제 DB 사용 증거. 충족 여부 현재 미확인 |
| R5 | 명료한 결과와 발표 | 실제 제출 발표와 프레이밍 토의 | 데이터에서 판단과 준비까지의 종단 시연, 검증 결과와 한계 | 수치와 화면이 입력 버전과 실행 기록으로 추적됨 |

인턴십은 [결과물 계약](12_최종_완료_계약과_결과물_형식.md)에서 독립 공고와 펠로우십 연계 활동을 구분한다. 현재 독립 인턴십 공고를 확보한 것으로 보고하지 않는다.

## 3. large-scale의 미해결 사항과 처리

활성 예제 10개만으로 공식 규모 요구를 충족했다고 표시하지 않는다. 과거 검색의 URL 수, 중복 콘텐츠 해시 수, 텍스트 청크 수는 유효 공고 적재 수가 아니다.

현재 신규 광역 수집은 중지돼 있다. 우선 기존 보관층을 읽기 전용으로 프로파일링해 원천 문서, 고유 사업, 모집 회차, 연결 가능한 유효 공고, 저장량을 분리한다. 실제 제품이 어느 DB 범위에서 어떤 질의를 수행하는지 확인한다. 현재 데모가 조회하지 않는 보관 자료를 제품 사용 규모로 합산하지 않는다.

M0에서 인정 범위와 현재 증거의 차이를 교수자에게 확인할 항목으로 올린다. 이번 문서 작업에서는 교수자에게 연락하지 않았다. 추가 수집이나 범위 확대가 필요하면 기존 자료로 가능한 대안과 일정 영향을 결정 기록에 남긴다. 같은 자료 복제로 규모를 만들지 않는다.

## 4. 공식 평가 항목과 발표 자료

26쪽의 항목은 다음과 같다.
- “Novelty: originality and creativity of the idea”
- “Impact: relevance and potential usefulness of the solution”
- “Technology: effective use of the techniques and tools covered in class”
- “Presentation: clarity and professionalism of the report and presentation”

| 항목 | 최종에 보여줄 자료 | 현재 빈칸 |
| --- | --- | --- |
| Novelty | 원문에서 적용 시점과 예외를 찾아 개인별 다음 행동과 문항 준비로 연결한 사례 | 기존 방식과의 같은 조건 비교 |
| Impact | 새롭게 안 관련 후보, 판정 오류와 확인 시간, 문항 충족과 작성 시간 | 실제 학생 결과와 시간 효과 미측정 |
| Technology | 수집 기록, 조건 스키마, 근거와 회차 연결, DB 조인, 갱신과 오류 처리 | 신규 추출과 의미 평가, 현재 DB 복구, 정기 실행 |
| Presentation | 실제 원문 → 구조화 → DB → 프로필 판정 → 개요와 초안의 한 흐름 | 대표 시나리오 동결과 백업 영상 |

LLM은 수집과 의미 해석, 경험 패턴 분석의 도구다. 처리 단계별 입력, 출력과 검증을 보여주고 모델 사용 자체를 성과로 세지 않는다.
