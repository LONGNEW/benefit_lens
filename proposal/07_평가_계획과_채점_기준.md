# 평가 계획과 채점 기준

## 1. 무엇을 성공으로 보는가

BenefitLens의 성공은 많은 공고를 모으거나 그럴듯한 글을 생성하는 것으로 판단하지 않는다. 등록 출처 안에서 기회를 찾는 시간과 오류를 줄이고, 사용자가 말하지 않은 사실 없이 공식 문항을 더 완전하게 작성하도록 돕는지를 측정한다.

## 2. 데이터 품질 평가

### 공고 데이터

- 같은 기간의 등록 출처를 사람이 직접 확인해 기준 공고 목록 작성
- 기준 목록 대비 발견 재현율
- 중복 제거 정확도
- 기간, 금액, 대상과 조건 추출 정확도
- 판정 상태별 정밀도와 재현율
- 잘못된 `조건상 검토 가능` 판정률
- 판정과 정확한 원문 버전의 연결률

개발 공고 30건과 분리된 평가 공고 20건 이상을 사용한다. 출처 계층, 문서 형식과 조건 유형이 평가 표본에 포함되게 한다.

### 작성 데이터

- 공식 문항과 글자 수 추출 정확도
- 서술 역할 주석의 두 사람 일치도
- 템플릿과 사용한 작성 자료 버전의 연결률
- 신청 양식 변경 시 재검토 상태 전환 여부
- 이용 권한이 없는 자료가 패턴 말뭉치에 포함된 건수

작성 자료 중 최소 3건은 템플릿 설계와 분리해 평가한다.

## 3. 사용자 비교 평가

동의한 성인 학생 8명에서 12명을 모집하고 순서 효과를 줄이기 위해 과제를 교차 배치한다.

### 탐색 과제

직접 공식 사이트를 보는 방식과 BenefitLens를 비교한다.

- 완료 시간
- 놓친 공고 수
- 조건 해석 오류 수
- 원문 근거를 찾는 데 걸린 시간
- 수집 실패를 실제 공고 부재로 오해한 횟수

### 작성 과제

빈 신청 양식 또는 일반 대화형 AI와 BenefitLens를 비교한다.

- 공식 문항 요구사항 충족률
- 사용자 입력에 없는 개인 사실의 수
- 사용자 확인 출처가 연결된 주장 비율
- 첫 초안까지 걸린 시간
- 사용자가 최종본을 만들기 위해 수정한 양
- 미완성 문항을 사용자가 발견한 비율

사용자 확인 출처는 진실성 증명이 아니다. 평가자는 사용자가 제공하지 않은 내용을 시스템이 추가했는지를 확인한다.

## 4. 시스템과 운영 평가

- 같은 입력 재실행 시 중복 생성 여부
- 변경 공고 수집부터 판정 갱신까지의 지연
- 양식 변경 뒤 기존 템플릿 사용 차단 여부
- 장애 뒤 재시도와 복구 여부
- 저장량, 일일 실행 시간과 서버 비용
- 주간 수동 검토 시간

## 5. 평가하지 않는 것

한 학기 안에 실제 장학금 합격률을 인과적으로 평가하기 어렵다. 공개 수기는 선발된 사람의 경험만 보여주고 탈락 사례와 심사 맥락이 부족하다. 따라서 합격률과 합격 가능성은 성과 지표로 사용하지 않는다.

전체 지원 생태계에 대한 재현율도 주장하지 않는다. 발견 재현율은 등록 출처와 고정된 기간 안에서만 계산한다.

## 6. 채점 기준과 증거

| 기준 | 발표에서 보여줄 증거 |
|---|---|
| Novelty | 조건 정규화와 수집 범위 공개를 공고별 신청 문항과 경험 기반 초안에 연결 |
| Impact | 탐색 시간과 오류, 초안 완결성, 근거 없는 주장, 작성 시간과 수정량 비교 |
| Technology | 이질적 수집, 조건 및 서술 역할 스키마, 증분 갱신, 버전 관리와 전체 계보 |
| Presentation | 수집 성공과 실패, 공고 변경, 경험 질문과 주장 점검을 한 흐름으로 시연 |

기술 이름만 나열하지 않는다. 모든 기술 요소는 실제 코드, 테이블, 실행 로그, 질의 또는 평가 결과에 대응해야 한다.
