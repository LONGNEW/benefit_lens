# 평가 계획과 채점 기준
기준일: 2026-11-04. 현재 예제 10개 범위의 평가 실행 규약이다. 아래 수치 목표는 팀 내부 제안이며 수업의 공식 합격 기준이 아니다.

## 1. 문제와 평가 질문

학생이 몰랐던 지원을 발견하고, 내 조건과 맞는지 확인한 뒤 준비 여부를 결정한다. 평가 질문은 세 가지다. 새롭게 알게 된 관련 후보가 있는가, 판단 정보가 원문과 맞는가, 준비에 필요한 사실과 문항을 빠뜨리지 않는가.

지원 횟수, 합격률과 지원금 합계를 성과로 사용하지 않는다. 발견 효과와 시간 감소는 측정 전까지 목표로만 쓴다.

## 2. 현재 기준선

| 검사 | 현재 값 | 해석 |
| --- | --- | --- |
| 저장 계약 | 11월 4일 10/10 통과 | 필드, 자료형, 참조와 날짜 순서 검사. 의미 정확도 아님 |
| 구조화 범위 | 9/10, 조건 잎 36개 | Gates 조건은 미구조화. 범위 지표 |

[현재 파일과 결과표](../evaluation/final/README.md)에 표본 목록과 기록을 둔다.

## 3. 표본과 정답 작성

현재 10개는 이미 개발에 사용한 회귀 표본이다. 무작위로 나눠도 완전히 독립적인 홀드아웃으로 부르지 않는다. 원문 없는 6개를 먼저 확보하되 이번 문서 작업에서 수집을 재개하지 않는다.

단위는 다음과 같다.
- 공고: 프로그램과 모집 회차 또는 회차 없는 제도 안내 한 건.
- 자격: 필드, 연산, 값, 단위와 척도, 적용 시점, 예외, AND/OR 경로를 가진 의미 조건 한 개.
- 혜택: 종류, 금액 성격, 통화, 기간과 지급 경로를 가진 항목 한 개.
- 문항: 공식 요구 내용과 분량을 가진 문항 한 개.
- 사례: 프로그램 안에서 구분한 신청자 사례. 같은 사람의 인터뷰와 제출문은 별도 문서일 수 있다.

두 검토자가 같은 원문 버전에서 독립 주석하고 불일치를 합의 기록으로 남긴다. gold는 present, not_stated, ambiguous를 구분한다. 모호한 조건은 정답을 억지로 확정하지 않고 미확인 판단 평가에 포함한다. 정답은 모델 출력에서 복사하지 않는다.

주석에는 opportunity_id, source_id와 원문 해시, 위치와 인용, 의미 항목, 경로, 두 검토자와 합의 결과를 남긴다. 현재 [정답 주석 템플릿](../evaluation/final/gold_annotations.template.jsonl)은 10건 모두 pending이며 정답이 아니다.

최종에는 입력과 정답, 코드와 프롬프트 버전, 모델, 실행 시각을 고정한다. 이후 수정하면 별도 실행 ID로 다시 평가한다.

## 4. 형식 검사와 의미 정확도를 분리한다

### 4.1 저장 형식
현재 validate_notice와 JSON Schema로 검사한다. 통과율의 분모는 입력 공고 수다. 조건이 null인 공고도 계약상 유효할 수 있으므로 구조화 범위를 별도로 보고한다.

### 4.2 추출 의미
정규화 뒤 값과 의미가 정답과 일치한 항목을 TP, 잘못 추가한 항목을 FP, 놓친 항목을 FN으로 센다. 잘못된 한 항목이 정답 항목을 대체하면 FP와 FN을 각각 하나 센다.

정밀도 = TP / (TP + FP), 재현율 = TP / (TP + FN), F1 = 2TP / (2TP + FP + FN). 분모가 0이면 NA로 표시하고 임의로 1을 주지 않는다.

- 조건은 값 외에 적용 시점, 예외와 논리 경로까지 맞아야 일치다. 일부 일치는 세부 오류표로 분리한다.
- 금액은 숫자, 통화, 최대/정액 성격과 지급 기간을 함께 비교한다.
- 날짜는 모집 회차와 시간대 또는 원문의 정밀도를 보존한다.
- 원문에 없는 값을 확정해 추가하면 근거 없는 항목으로 센다.
- 문자열 인용 존재와 그 인용이 주장을 뒷받침하는지는 별도 지표다.

공고별 결과와 전체 micro 합계를 함께 보고한다. 출처, 형식과 조건 유형별 표본 수도 적는다. 원문 확보 4개와 요약 6개를 한 정확도 분모로 섞지 않는다. 새 LLM 추출을 실행하지 않았다면 검토 표본의 원문 감사 결과라고 명명한다.

### 4.3 개인 조건 판정
원문 정답을 기준으로 프로필과 공고의 기대 결과를 검토자가 먼저 작성한다. 현재 코드의 출력을 정답으로 삼지 않는다.

기본 일치, 불일치, 미확인과 추가 조건의 예외를 구분하고 모집 상태를 별도로 비교한다. wrong-pass는 정답이 불일치 또는 미확인인데 시스템이 최종 검토 가능으로 단정한 경우다. 기본 조건 일치 표시 자체와 최종 접수 가능을 혼동하지 않는다.

현재 11개 기능 시나리오를 회귀 검사로 유지하고, 각 공고에서 가능한 충족, 불충족과 정보 누락 프로필을 추가한다. 불명확한 Gates에 억지로 충족 프로필을 만들지 않는다. 최종 표에는 실제 조합 수와 상태별 혼동행렬, 정밀도와 재현율, 미확인 비율을 함께 남긴다.

### 4.4 작성 결과
현재는 개요를 평가하고, 문장 초안을 연결한 뒤 같은 기준으로 확대한다.
- 문항 충족률: 다룬 공식 요구 항목 수 / 전체 요구 항목 수.
- 사용자 사실 외 추가 건수: 사용자 입력과 제공한 근거에서 뒷받침되지 않는 개인 사실 수.
- 주장 근거 연결률: 연결된 개인 사실 주장 수 / 전체 개인 사실 주장 수. 출처 연결과 진실성은 구분한다.
- 분량 준수와 누락 질문: 실제 공식 문항에서 점검.
- 패턴 근거: 인용 일치와 사례 연결의 유효성, 프로그램과 회차의 적합성을 검토자가 확인.

선정과 미선정 사례의 관찰 차이를 합격 원인으로 채점하지 않는다.

## 5. 내부 종료 목표

| 지표 | 제안 목표 | 실패 시 처리 |
| --- | --- | --- |
| 저장 계약과 필수 참조 | 평가 입력 전부 통과 | 적재 또는 공개 결과에서 차단 |
| 모집 마감, 금액 단위와 최대/정액 의미 | 평가 표본 오류 0건 | 해당 결과 수정 후 재평가 |
| 필수 자격과 예외 누락, wrong-pass | 평가 표본 0건 | 미확인으로 보류하고 조건 수정 |
| 조건과 혜택의 의미 항목 | 정밀도와 재현율 각각 0.95 이상 | 오류 유형과 분모를 공개하고 재평가 |
| 원문 근거 연결 | 공개한 판단 항목 전부 연결 | 연결 없는 확정 설명을 내리지 않음 |
| 실제 문항의 초기 초안 | 필수 요구 누락 0, 근거 없는 개인 사실 0, 분량 준수 | 추가 질문이나 빈칸으로 돌림 |
| 재적재와 갱신 | 동일 입력의 중복/이력 증가 0, 실패 가시화 | 공개 갱신을 중단하고 복구 기록 |
| 제품 실행 | 제출 환경에서 대표 시나리오 전부 통과 | 기능 동결 전에 복구 |

오류 0건은 평가한 작은 표본의 종료 기준이며 전체 환경의 오류 확률 0을 뜻하지 않는다. 0.95는 초기 목표다. 사전 등록한 기준을 낮추면 이유와 변경 시점을 남기고 실패 결과를 보존한다.

## 6. 발견과 사용자 효과의 최소 평가

실제 학생 5~10명의 소규모 탐색 평가를 제안한다. 연락과 모집은 아직 하지 않았다. 먼저 알고 있는 지원을 적게 한 뒤 표본을 보여주고 사전 인지, 기본 관련성, 검토 의향과 다음 행동을 기록한다. 처음 보았고 기본 요건 검토를 통과한 공고 수를 참가자별로 보고한다. 이 조사는 전체 학생의 놓침 규모를 추정하지 않는다.

이후 동일 프로필과 공고로 제목/금액/링크만 있는 결과와 근거/조건/제약/준비물이 있는 결과를 비교한다. 순서를 교차 배치하고 판단 정확도, 추가 확인 항목과 완료 시간을 함께 기록한다. 작성 비교는 동일한 본인 사실과 공식 문항을 주고 개요/초안의 충족률, 사실 추가와 수정 시간을 비교한다.

정확도를 유지한 상태의 시간 감소를 본다. 참가자 단위 결과와 중앙값을 제시하고 작은 표본에서 일반적인 효과나 합격률 개선을 주장하지 않는다.

## 7. 갱신과 시스템 평가

일 단위 갱신은 목표 운영 주기다. 매일 실행 여부, 출처별 성공/실패, 이전과 현재 해시, 신규/변경/불변, 재시도와 지연을 7일간 기록한다. 자료가 실제로 바뀌지 않으면 통제된 변경 표본을 함께 시험하고 실제 웹 변경과 구분한다.

DB 규모는 고유 사업, 모집 회차, 원천 문서, 사례, 패턴과 저장량을 분리한다. 대표 질의는 표본 범위, DB 버전과 하드웨어, 인덱스, 캐시 조건을 기록하고 5회 측정의 중앙값과 최댓값을 보고한다. 수집과 모델 처리 비용, 요청 시 비용도 나눠 기록한다. 명령과 측정 파일을 만들기 전에는 성능 수치를 채우지 않는다.

과제의 평가 항목과 제출 증거는 [11 문서](11_과제_요구사항_충족_계획.md), 사용자 결과 형식은 [12 문서](12_최종_완료_계약과_결과물_형식.md)를 따른다.

## 8. 개인 자료와 공개 검색을 연결한 신규 경로 평가

아래 평가는 [개인화 근거 수집 명세](13_개인화_근거수집과_작성지원_명세.md)의 신규 기능을 위한 계획이다. 제품에 연결되지 않았고 정확도도 미측정이다.

| 평가 대상 | 독립 정답과 계산 단위 | 필수 오류와 내부 목표 |
| --- | --- | --- |
| 요구에서 필요한 사실 도출 | 검토자가 요구별로 작성한 필드, 시점과 자료 목록 대비 정밀도/재현율 | 판단에 필요한 필수 필드 누락을 별도 집계 |
| 공개 자료의 동일인 연결 | 사용자 지정 식별자와 검토한 소속/이력으로 주체 정답 작성 | 잘못된 사람의 accepted 사실 병합 0건 |
| 개인 사실 보강 | 원문, 주체, 적용 시점과 값이 맞는 accepted 사실 / 검토한 accepted 사실 | 추정한 수료나 본인 역할의 확정 사용 0건 |
| 규칙 계산과 의미 추론 | 부모 사실과 규칙으로 재계산, 해석 후보는 별도 주석 | 확인되지 않은 의미 추론의 최종 사용 0건 |
| 필요 서류 | 실제 공식 요구별 자료 종류와 필수/조건부 여부 | 공식 양식, 개인 발급 자료와 참고 사례의 혼동 0건 |
| 서류 확보 | 회차, 자료 역할, 실제 확보 상태와 URL을 원문으로 확인 | 과거 양식 대체, 확보하지 않은 파일을 found로 표시한 건수 0 |
| 작성 지침 | 지침별 인용의 뒷받침, 관찰 범위와 현재 문항 적합성 | 결과 라벨만으로 쓴 탈락 원인과 합격 공식 0건 |
| 문항별 초안 슬롯 | accepted인 본인 사실, 연결 지침과 부족한 질문 대조 | 타인 사례와 미확인 후보를 개인 성과로 쓴 건수 0 |

선정, 미선정과 결과 미상 사례를 각각 포함한다. 공개 발췌와 전체 원고도 나누고, 관찰한 범위를 넘어선 결함 판정을 오류로 센다. 다른 프로그램 지침의 전이를 숨기면 별도 오류다.

현재 [계약 예시 검사](../evaluation/spec_examples/README.md)는 합성 자료의 구조와 교차 참조, 확인 전 사용 차단을 검사한다. 실제 검색의 동일인 정확도나 지침의 의미 타당성을 검증한 결과가 아니다.
