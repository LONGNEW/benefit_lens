# 1팀: 공통 표현과 공고별 정보의 승인 규격

## 문제 시나리오

교과 수료 전인 학생이 Google과 현대모비스 공고를 검색한다. 두 공고 모두 교과 이수를 언급하지만 한 조건은 수혜 시작까지 대부분 이수, 다른 조건은 신청 시점의 수료다. 표현은 함께 검색할 수 있어도 같은 사실로 판정할 수 없다.

## 현재 문제와 확인한 근거

`020_proposal_pipeline.sql:22`는 식별과 유형을 SQL 열로, 자격과 혜택, 지원 정보를 JSONB로 저장한다. `proposal_pipeline.py:336`의 기존 인용 검사는 구절 존재를 확인한다. 역할, 시점과 문장 뜻의 일치까지 승인하는 배치 규격은 아래 제안이다.

| 확인한 문구 | 구조화할 때 남길 차이 |
| --- | --- |
| Google 원문 159행 “completed most of their graduate coursework”, 모비스 표본 “② 박사 : Coursework 수료자” | 대부분 이수와 완전 수료를 같은 값으로 바꾸지 않는다. 박사와 현재 미수료를 기존 함수에 넣으니 Google의 해당 항목은 미확인, 모비스의 코딩된 조건은 불충족이다. |
| 관정 원문 105행 “학기당 금액”, 표본의 A형 “600 만원” | KRW 600만, 학기 단위다. 금액 구절만 파싱하면 주기는 null이다. `매월 50만원 지원`과 `500,000원/월 지원`은 단위까지 명시된 통제 예시에서 일치했다. |
| NVIDIA 원문 34행 “required in-person summer internship before the award year” | 펠로우십과 그 수행 의무를 나눈다. 독립 인턴십 공고로 세지 않는다. |
| Campus France 원문 341행 “for more information on housing allowance and tuition fees, please contact your mobility officer.” | 주거비 검색 표현의 근거다. 해당 회차의 지급 조항은 아니다. |

추가로 POSTECH 보도 링크의 “석사과정생 월 150만 원이 지급되며, 최대 4학기까지 수혜가 가능하다”에서 현재 금액 파서가 기간의 최대를 금액 상한으로 읽었다. 금액, 지급주기, 기간 상한과 대상은 각각 근거를 연결해야 한다. [검산](checks.json)은 보관 자료와 순수 함수의 6개 대조 및 이 오류 1건을 기록한다. 최신 공고나 전체 추출 정확도를 재검증한 결과는 아니다.

## 설계와 작업 순서

1. **공통화 기준:** 검색 사전의 `related/broader`와 필드 사전의 `equivalent/non_equivalent/undetermined`를 분리한다. 판정상 동치는 대상, 술어와 범위, 적용 시점, 단위, 예외와 강제성이 같은지 확인한다. 근거는 출처 버전, 추출본 해시, 구절과 문맥을 고정한다. OR 경로와 부정은 트리에 남긴다.
2. **저장 경계:** 프로그램/회차/버전, 조회용 유형, 기관, 날짜와 상태는 검증된 SQL 열로 둔다. 조건, 혜택 구성, 신청 서류와 문항, 프로그램별 추가 속성은 버전 있는 JSONB로 둔다. 유형, 혜택, 참여 의무, 제출 경로와 수집 채널은 별도 축이다. 공통 필드도 반복 구조라면 JSONB에 남길 수 있다. 별도 MongoDB는 이번 단계에서 요구되지 않는다.
3. **보류와 승격:** 매핑 상태를 accepted, unmapped, ambiguous, conflict, rejected로 둔다. 미해석 값은 원문과 질문을 유지하고 자격 자동 비교에서 unknown으로 둔다. 자주 발견되거나 중요한 특수 필드는 검토 대상으로 올린다. 의미 동치와 반례, 회차별 적용 범위를 검수한 뒤 사전 버전을 올린다. SQL 열 승격은 별도 질의 측정으로 결정한다.
4. **재처리:** 1팀은 이전/새 사전, 변환기, 평가기와 원문 버전을 고정한다. 영향받은 항목만 같은 자료로 재처리해 이전 판정과 나란히 남긴다. 2C가 판정 차이와 D1 투영을 독립 대조한다. 의미 변경은 새 판정으로 발행하고 구 판정은 이력으로 남긴다.

## 매 배치 왕복

2팀은 batch/candidate/query ID, 문서와 추출본 버전, URL, 구절/위치, 역할과 회차 후보, 변경 분류를 보낸다. 1팀은 수신 ACK를 먼저 반환하고, 별도 결정에 매핑 상태, 이유, 추가 확인, 사전 버전, 승인한 회차/문서 버전과 갱신 대상을 기록한다. 같은 batch ID의 내용은 불변이다. 문서의 표면 변경과 자격/혜택/첨부 변경을 나눠 재연결 또는 해당 주장만 재검토한다. [왕복 예시](batch_example.proposed.json)는 검색어는 유지하고 지급 주장은 거절하는 한 건이다.

상위 팀의 공동 Claude 1/2차를 읽고 팀 경계와 중단 조건을 반영했다. 1팀은 별도 호출하지 않았다. 발견 관계만으로 의미를 승인하지 않는다. 첫 통합에서 근거 없는 승인 값, unknown을 false로 바꾼 판정이 하나라도 나오면 발행을 중단한다. 이번에 한 일은 저장 원문 검산과 규격 설계다. 새 사전, 배치 API, 마이그레이션과 과거 재처리는 실행하지 않았다.
