# 3팀: 작성 패턴 설계와 초안 작성

연구계획서를 쓰는 학생은 자신의 실험에서 무엇을 근거로 쓸지 막힌다. **공고와 확인된 경험을 공통 기준으로 두고, 일반 작성 원칙과 사례가 어떤 선택지를 더 주는지 비교한다.** 사례를 보태는 것이 더 좋다는 결론은 아직 없다.

## 현재 문제와 근거

[NVIDIA 안내](https://research.nvidia.com/graduate-fellowships)의 보존 회차는 연구계획 본문과 그림 2쪽, 참고문헌 별도다. 연구 비전, 현재까지의 성과와 GPU 관련성은 작성 및 평가 안내다. 과거 NVIDIA 인턴 경험 서술은 해당할 때의 권고다. 대면 인턴 수행 가능 여부라는 별도 요구와 다르다. [NSF 안내](https://www.nsf.gov/funding/initiatives/grfp/how-to-apply)는 연구계획 2쪽에 참고문헌을 포함하고 두 제목을 요구한다. 분량 계산과 필수 제목은 공고마다 다시 읽어야 한다. [Lu 외 원 연구](https://digitalcommons.memphis.edu/facpubs/18089/)는 논문 서론 500편에서 분야별 수사 전개 차이를 보고했다. 문장 기능을 관찰하는 데 참고할 수 있으며 지원서의 최적 순서나 효과를 시험하지 않았다. [원문 인용과 범위](sources.md).

기존 검증기는 인용과 사례 귀속을 확인하지만, 읽기 전용 검사에서 지원문을 인터뷰로 바꿔도 통과했다. 비교 보류는 거절됐다. 품질 측정 근거로 쓰지 않으며 새 역할 및 비교 보류 검증은 미구현이다.

## 역할과 계약

| 역할 | 입력 → 출력 | 완료 조건 |
| --- | --- | --- |
| 3A 패턴 설계 | 회차별 공식 문항, 책과 논문 및 기관 안내, 사례 원문 → 범위가 표시된 작성 지침 후보 | 원문 구절과 주장 연결, 역할과 회차 검토, `candidate`에서 `reviewed`로 승인, 유효 버전 보존 |
| 3B 초안 작성 | 대상 문항, 검토된 지침, 본인의 `accepted` 사실 → 문항별 슬롯, 초안 또는 질문 | 공식 제약 우선, 문장별 사실 ID, 같은 경험의 역할과 결과 연결, 계획과 성과 구분 |

3A는 필수 형식과 내용, 평가 기준, 선택 서술을 따로 반환한다. 공고가 강제하는 제약은 사례나 책에서 가져온 구조보다 우선한다. 토론은 새 구조나 반례를 제안하고, 채택 근거는 원문과 연결한다. 현재 문항과 기능이 맞는 지침만 전이하며 공식 요구가 바뀌면 재검토한다. 읽는 이의 질문, 본인 행동, 결과와 한계를 잇는 원칙은 후보이며 특정 순서를 강제하지 않는다.

공개 지원문, 인터뷰, 후기는 다른 역할이다. 공개문은 관찰한 구조, 인터뷰와 후기는 귀속된 경험이나 조언을 준다. 예를 들어 N2의 연구문과 패널은 같은 사람이며 정확한 최종 제출본과 당시 문항 연결은 미확인이다. 수집팀과 해당 자료는 잠정 관찰로 넘기고 특정 비교에 필요할 때만 추가 확인하기로 했다. 화자와 문항은 구절 단위로 붙이고, 한 사람의 여러 문서를 독립 사례로 세지 않는다.

LLM에는 승인 범위의 원문을 제공하고 문서 버전, 처리한 구획, 누락, 한도와 실패를 기록한다. 한도를 넘으면 문서를 나눠 구절 관찰을 모으고, 누락을 표시한다. 최종본이 없거나 문항과 공개 범위가 다르면 한정 대비 또는 `no_comparable_pair`를 반환한다. 결과와 무관하게 유용한 구조나 보강 질문을 남긴다. 선정 여부로 글의 우열을 가리지 않는다.

3B는 사례의 성과와 문장을 가져오지 않는다. 확인된 본인 역할과 결과도 같은 `experience_id`일 때만 한 주장으로 쓰고, 사실이 모자라면 질문을 반환한다. 지침을 채우는 정보는 새 지원 자격이 아니다.

## 같은 입력으로 해 본 작은 점검

보존 NVIDIA 회차의 원문 해시와 저장된 문항 제약을 확인했다. 합성 사용자 한 명의 버퍼 재사용 경험으로 [세 슬롯 예시](slot_examples.json)를 직접 작성했다. 공식 제약과 사실은 세 군에 공통이다. 일반 원칙은 병목부터, 사례는 공통 연구 목표부터 시작한다. 혼합은 두 순서가 주는 정보가 같아 중복 지침을 채택하지 않았다. 세 방식 모두 같은 A100 조건에서 지연시간 60→45ms라는 합성 결과와 다음 검증 계획을 담았다. 사례는 순서의 선택지를 줬고 혼합은 새 질문을 보태지 않았다.

예제 검사에서 세 정상 안이 통과했고 타 경험 결과 결합, 미확인 주장, 타 기관 형식, 선정 주장, 계획의 성과 전환을 각각 차단했다. 검사 대상은 예제의 필드와 참조다. 문장 의미, 실제 분량, 사용자 효용과 선정률은 측정하지 않았다.

## 공동 토의와 다음 작업

공동 Claude의 공식 형식 우선, 현 검증기의 한계, 미사용 프로그램을 떼어 평가하자는 제안은 채택한다. 비교군마다 공식 입력을 다르게 주면 어떤 근거가 개선했는지 알 수 없다는 점은 독립 판단이다. 다음에는 공식 요구와 본인 사실만 준 기준군을 더해 네 군을 같은 조건에서 평가한다. 검토자는 문항 충족, 사실 근거, 새로 발견한 준비 질문과 불필요한 반복을 비교한다. 새 역할 검증과 비교 보류를 먼저 구현하고, 미사용 프로그램에서 일반 지침의 전이와 사례의 추가 가치가 재현되는지 본다.
