# 제품 범위와 사용자 흐름

## 1. 대상과 범위

첫 버전의 사용자는 POSTECH 재학생이다. 장학금을 첫 검증 도메인으로 삼고 기회 출처를 다음 네 범주로 관리한다.

| 범주 | 대상 |
|---|---|
| 학교 | 공개 접근 가능한 교내 장학과 금전 지원 |
| 재단 | 공개 모집 회차와 신청 문항을 확인할 수 있는 장학재단 |
| 기업 | 기업 또는 기업 연계 기관이 운영하는 공개 지원 프로그램 |
| 국가 | 공공 API 또는 공식 포털에서 확인 가능한 국가 지원 |

학교 출처는 POSTECH 한 곳으로 고정한다. 재단, 기업과 국가는 각 3개씩 연결해 목표 포트폴리오를 총 10개로 잡고, 수집 안정성과 운영 비용을 확인한 뒤 세 범주만 각 4개까지 늘린다. 종단 간 데모는 범주별 한 출처의 대표 공고를 먼저 검증하며, 현재 공고와 최근 12개월의 변경 이력만 다룬다.

작성 단계는 공개 공식 양식이 있는 신청 유형 하나와 이용이 허용된 작성 자료 5건에서 10건으로 제한한다.

## 2. 1단계: 지원 기회 찾기

1. 사용자가 학적, 거주지, 연령, 성적과 소득 등 최소 정보를 입력한다.
2. 시스템이 등록 출처의 공고 조건과 대조한다.
3. 전체 검색 결과를 개인 조건으로 판정한 뒤 접수 가능, 조건 미충족, 확인 필요, 접수 예정, 마감으로 나누고 페이지를 나눈다.
4. 각 판정의 조건 값, 근거 문장, 원문 버전과 수집 시각을 보여준다.
5. 사용자는 공식 원문을 확인할 공고 하나를 고른다.

결과가 없으면 “지원이 없다”고 표시하지 않는다. 등록 출처의 정상 수집 구간에서 조건에 맞는 공고를 찾지 못했다고 표현한다. 출처 수집이 실패했다면 결과가 불완전하다는 경고를 먼저 보여준다.

학교는 POSTECH 전체의 공통 장학제도와 학과별 공개 지원을 탐색한다. 카드에는 지원 자격, 조건, 혜택, 특약, 기간만 먼저 표시한다. ‘접수 가능’은 구조화된 모든 필수 조건과 확인된 접수 기간을 함께 통과해야 한다. 상시 제도는 현재 모집과 분리하고 공개 대상 범위가 맞으면 ‘제도 대상 가능’으로 표시하며, 세부 선발 기준은 공식 안내 확인 항목으로 남긴다.

## 3. 2단계: 자기 경험으로 쓰기

1. 선택한 공고 버전에 연결된 공식 신청 문항과 글자 수를 불러온다.
2. 각 문항이 요구하는 동기, 행동, 근거, 결과와 향후 계획을 확인한다.
3. 시스템이 사용자의 실제 경험을 묻는 질문을 순서대로 제시한다.
4. 사용자가 답변을 확인하면 개요를 만든다.
5. 확인된 답변만으로 첫 초안을 만든다.
6. 각 주장을 사용자 답변에 연결하고 미확인 사실과 누락 문항을 표시한다.
7. 사용자가 내용을 수정하고 사실을 최종 확인한다.

입력에 없는 수상, 성과, 활동, 가족 사정과 수치는 만들지 않는다. 정보가 부족하면 그럴듯한 문장 대신 추가 질문을 제시한다.

## 4. 두 단계의 연결점

2단계는 별도의 자기소개서 생성기가 아니다. 다음 데이터가 1단계에서 그대로 넘어온다.

- 사업과 모집 회차
- 신청 기간과 현재 상태
- 공식 신청 양식의 버전
- 자격 조건과 부족한 증빙
- 운영기관과 공식 원문

공고나 양식이 바뀌면 기존 템플릿을 자동 수정하지 않는다. 관련 초안 기능을 재검토 필요 상태로 바꾸고, 사람이 문항 연결을 다시 확인한 뒤 새 템플릿 버전을 공개한다.

## 5. 최종 사용자 행동

> 오늘 검토할 공고 하나를 고르고, 부족하거나 확인할 조건을 이해한 뒤, 공식 문항에 맞추어 자기 경험으로 작성한 검토 가능한 첫 초안을 얻는다.
