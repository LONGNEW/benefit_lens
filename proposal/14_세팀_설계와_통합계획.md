# BenefitLens 팀 구조와 첫 연결

2026-11-19의 팀 구성, 책임 경계와 검증 계획은 [최신 팀 구성안](15_팀구성과_검증프레임워크_20261119.md)을 따른다. 아래는 초기 세 팀의 설계와 구현 기록이다.

## 문제 시나리오

학생이 자기 조건에 맞는 지원을 찾고, 공식 서류와 본인 경험으로 초안을 준비한다. 검색을 넓히면 같은 공고의 다른 문서와 비슷한 표현이 섞인다. 문서가 늘어도 실제 기회가 늘었는지 확인해야 하고, 글의 형식은 현재 문항마다 다르다.

## 현재 문제와 확인한 근거

- **공통 의미:** Google의 수혜 시작 시점 교과 이수 조건은 현재 완전 수료와 다르다. NVIDIA의 연계 인턴십은 펠로우십 수행 의무다. 금액 파서는 “최대 4학기”를 지급액 상한으로 읽었다. 관련어를 연결해도 시점, 역할과 단위는 따로 보존해야 한다.
- **수집 범위:** 기존 10개는 장학 6개, 펠로우십 3개, 진학 지원 1개다. 기관 소재국은 한국 7개, 미국 2개, 영국 1개이며 지원자의 국적 조건과 별개다. 과거 실행의 수집 성공 URL 6,240개 중 원본 해시는 6,115개다. 고정 표본 12개를 확인하니 특정 회차 기관 공고나 규정 후보 2개, 양식 2개, 안내와 보고서 등 8개였다. 전체 승인율은 미측정이다. [공고 집계](팀별설계/검토기록/sample_inventory.json), [문서 역할](팀별설계/검토기록/source_role_labels.json).
- **작성 방식:** 일반 조언을 그대로 적용하면 공식 문항과 충돌할 수 있고, 사례만 읽으면 비교할 자료가 없는 문항을 다루기 어렵다. 3팀이 같은 NVIDIA 문항과 합성 경험으로 일반 원칙, 사례, 혼합을 대조했을 때 이 한 예에서는 혼합이 새 사실이나 질문을 보태지 않았다.

## 역할과 인계

| 담당 | 하는 일과 산출물 |
| --- | --- |
| [1팀 스키마](팀별설계/schema/team_report.md) | 기관, 회차, 상태 등 조회 키는 SQL, 복합 조건과 프로그램별 문항은 타입이 있는 JSONB로 둔다. 뜻, 단위, 기준일과 적용 대상을 대조해 공통 필드 매핑을 승인한다. |
| [2팀 수집과 검증](팀별설계/discovery/team_report.md) | 2A는 공고와 양식, 2B는 지원서와 인터뷰 및 후기를 수집한다. 2C는 별도 기준표로 역할과 중복, 고유 승인 회차, 편중, 확장 비용을 검증한다. |
| [3팀 패턴과 초안](팀별설계/writing/team_report.md) | 3A는 공식 문항에 맞는 작성 원칙과 사례의 쓰임을 고른다. 3B는 같은 경험에서 확인된 본인의 역할과 결과로 슬롯을 채우고, 부족하면 질문한다. |

2팀은 배치마다 검색 경로, 문서 역할 후보, 원문과 버전, 인용 위치, 회차 후보를 넘긴다. 1팀은 항목별 승인, 보류, 반려와 이유를 회신한다. 검색 사전의 관련어와 판정 사전의 동치를 분리한다. 매핑을 고치면 1팀이 영향받는 항목만 새 버전으로 재처리하고, 2C가 이전 결과와 대조한다. 3팀은 사례 채택 여부와 부족한 문항 자료를 2B에 돌려준다.

## 선택과 검증 기준

- **스키마:** 공통 조회값은 고정하되, 새 표현은 근거와 함께 먼저 후보로 받는다. 기존 의미와 같을 때만 연결하고, 여러 공고에서 반복 사용되는 필드는 버전 있는 공통 정의로 승격한다. 미래 시점, 단위와 예외가 사라지면 해당 매핑을 보류한다.
- **확장:** 고정 초기 사전과 확장 사전에 같은 질의 예산을 주고, 사전에 쓰지 않은 기관과 회차에서 승인된 고유 기회와 오류, 검수 비용을 비교한다. 출처와 지원 방식의 다양성, 저장량과 처리 속도는 별도로 측정한다. 현재 기록으로 웹 전체 포괄성이나 운영 용량을 확정할 수 없다.
- **작성:** 공식 문항과 확인된 본인 사실을 항상 사용한다. 일반 원칙은 구조 후보로 두고, 사례가 문항에 맞는 새 질문이나 구성 선택을 줄 때 추가한다. 두 입력을 고정해 일반 원칙, 사례, 혼합을 비교하고 문항 기능과 형식 범위를 맞추고, 형식 위반, 근거 없는 사실과 유용한 질문을 따로 평가한다. 개별 효과까지 주장하려면 보조 자료 없는 군도 둔다.

## 진행과 다음 작업

재집계, 팀 간 반례 검토, 문항 예시와 공동 Claude [1차](팀별설계/검토기록/claude_round1.txt), [2차](팀별설계/검토기록/claude_round2.txt)를 마쳤다. 비교군의 공식 요구와 사용자 사실을 통일하고 형식 차이의 영향을 분리했다.

2026-11-09 [팀 인계 계약](../docs/specs/team-handoff.md)과 로컬 조정기를 구현했다. 수집팀의 기존 원천 모집건 4,339개, 스키마팀의 5개 기관 6개 모집 변형과 명시 매핑 7개, 작성팀의 NVIDIA 과거 회차 사례 3개와 패턴 2개를 연결한다. 잘못된 회차, 누락 원문, 변경된 승인 입력과 미확인 사용자 사실은 보류하거나 질문으로 반환한다. [결과 보고](결과물/팀간인계_2026-11-09/README.md)에 실제 검증과 실행 경로를 기록한다. 운영 적재, 새 광역 수집, 확장 효과와 완성 초안 품질 비교는 후속 작업이다.

후속 실행에서 신규 현재 모집 변형 39개와 부모 후보 36개, 공통 매핑 27개, NSF GRFP와 Fulbright 경험 자료를 추가했다. 원형과 합친 원문 검증과 변경 자료의 SQL 검증 표본 실행을 마쳤다. 최신 규모와 남은 범위는 [증분 확장 결과](결과물/증분확장_2026-11-09/README.md)를 따른다.
