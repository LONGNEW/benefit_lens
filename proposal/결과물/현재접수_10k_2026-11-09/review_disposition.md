# 등록기 교차 검토 반영

Claude CLI의 읽기 전용 검토는 당시 코드에 대해 “신원 네임스페이스 혼용”, “마감 시간대”, “집중도 미공개” 등을 제기했다. 검토 결과는 claude-review.json에 보존했다. 아래는 실제 수정과 범위 판단이다.

| 쟁점 | 반영 및 확인 |
| --- | --- |
| 같은 Workday 공고의 별칭 중복 | 실제 공개 URL에서 tenant를 추출해 identity를 고정했다. 다른 tenant의 같은 native ID는 별개이고, 같은 tenant의 여러 공개 사이트 게시물은 같은 공고로 합친다. |
| Mercedes ID 대소문자 | identity를 대문자로 정규화했다. |
| 같은 시각의 충돌 | 원문 해시나 핵심 필드가 다르면 오류로 중단한다. 메타데이터 차이는 입력 순서와 무관한 정렬로 선택하고 감사 기록을 남긴다. |
| 짧은 ID 부분 문자열 | 영숫자 경계 검사와 개별 원천의 복합 URL 식별자를 사용한다. 목록의 실제 공고 URL도 대조한다. |
| 보조 원문과 수집일 | 학생 지침, 과정, 학과 모달, 마감과 개시 안내의 원본 및 텍스트 해시를 연결한다. 같은 기관과 적용 범위, 명시된 시간대와 당일 수집을 확인한다. |
| JSON 상태와 URL | Workday의 canApply, posted, jobReqId, externalUrl, SmartRecruiters의 active, visibility, postingUrl, applyUrl을 원본과 대조한다. |
| HTML의 신청 링크 | 당일 목록과 학생 조건, 원문의 신청 링크와 명시된 기간을 결합한다. Walmart는 같은 ID의 공식 SSR과 실제 클라이언트 조건을 따로 확인했다. |
| 유형 기본값 | 기본값을 other로 두고 학생 근로를 인턴으로 잘못 부르던 분류를 수정했다. |
| 게시 종료와 신청 마감 | Mercedes PublicationEndDate와 Schneider posting_expiry_date는 게시 기한으로 보존한다. 실제 신청 기한이 없으면 SQL closes_on은 비워 둔다. |
| 불변성 | 출력 경로, 보고서와 선정본이 있으면 덮어쓰지 않는다. 입력 파일을 해시로 고정한다. |
| 집중도 | 최종 통계에 issuer별 수, 상위 비중과 제목별 반복 문안 집계를 포함한다. |

“증거 위치자 비정확”이라는 지적은 검토에 전달되지 않은 DB 검증 코드의 validate_sources가 이미 전체 원문 위치와 인용문을 대조하고 있었으므로 전면 누락으로 해석하지 않았다. 문자 끝 위치를 LF 줄로 변환할 때의 경계는 수정했다. 실제 PDF 검토에서 splitlines가 form-feed를 새 줄로 세는 차이를 발견했고, LF 계약에 맞춰 재검산해 기존 인용을 유지했다.

날짜만 공개된 원천은 마감 당일의 정확한 시각을 확정할 수 없다. 최종 공고는 2026-11-09의 수집 시점 상태를 기록한다. 로그인 이후 양식 완성이나 실제 지원 제출은 실행하지 않았다. 개인별 전체 자격을 확인하는 full_eligibility_verified는 false로 남긴다.

Schneider 예비본은 전처리 파일을 같은 경로에 다시 써 해시가 달라진 문제를 발견했다. 예비본은 최종 입력에서 제외하고, 내용 해시가 포함된 텍스트 경로를 쓰는 새 고정본을 받는다.
