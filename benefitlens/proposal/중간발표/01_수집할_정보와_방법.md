# 학생 개인 대상 예제 10개의 입력 자료와 확보 방법

## 문제 시나리오와 범위

학생이 공고를 찾고 자격을 확인한 뒤 공식 문항을 작성하려 한다. 현재 프로젝트는 학생 개인 대상 예제 10개에서 공고, 공식 양식과 경험 원문을 연결한다. 일반 기관 연구비와 교원 전용 사업은 제외하며 신규 검색과 크롤링은 중지했다.

예제는 NVIDIA, Google 동아시아, 관정 학부, Gates Cambridge, POSTECH AX, POSTECH K-탑티어, 포스코 해외유학, 현대모비스 연구장학생, 대통령과학장학금과 희망사다리 I유형이다. 국내외 범위를 보여주되 예제 일부는 과거 회차와 공통 조건만 담는다.

## 무엇을 입력으로 사용하는가

| 자료 | 처리할 정보 |
|---|---|
| 공식 공고 | 기관, 사업, 회차, 자격, 혜택, 기간과 신청 경로 |
| 공식 양식과 안내 | 문항, 분량과 제출 서류 |
| 경험 원문 | 공개 지원서, 후기, 인터뷰, 작성자가 공개한 자료 목록 |

이번 실행은 이미 확보한 파일을 사용한다. 원문은 공개 표본 Git에 재배포하지 않고 URL과 프로젝트가 작성한 요약을 제공한다.

## 기존 검색은 브라우저를 여는가

기존 검색 확장에서는 에이전트가 웹 검색 도구를 호출했다. 이 도구의 응답에는 제목, URL과 발췌가 들어 있다. 시각적인 브라우저를 열고 검색창에 입력하는 단계는 필수 경로가 아니다.

실행 구조는 `SearchLoop.next()`의 질의 선택 → 에이전트의 검색 도구 호출 → 검색 응답 JSON 저장 → `reconcile()`의 실행 기록 확인 → `Frontier.collect()`의 Python HTTP 요청이다. 크롤러는 HTML에서 본문과 링크를 추출하고 PDF 및 한글 첨부를 저장한다. 검색 도구 호출 자체는 이 Python 모듈 안에 구현돼 있지 않다.

## Python과 LLM의 역할

Python은 URL 요청, 응답 보존, 텍스트 변환, 중복과 실행 상태를 처리한다. LLM은 텍스트를 읽어 문서 역할, 자격 의미와 작성 패턴을 해석한다. LLM이 브라우저로 읽는 경우와 정보의 원천은 같을 수 있다. 파일과 URL 확보를 코드로 고정하면 같은 원문을 다시 분석하고 결과를 비교할 수 있다.

## 검색 표현의 원문 검사는 무엇인가

`add_term()`은 확보한 원문에 후보 표현이 있는지 검사한다. 예를 들어 원문에서 찾았다고 한 `Research Plan`이 실제로 등장해야 채택한다. 이는 출처 확인을 위한 더블 체크다. 표현이 유용한 검색어인지, 자료를 충분히 찾았는지는 별도 판단이다. 현재는 검색을 중지했으므로 이 루프를 더 실행하지 않는다.

## 발표에서 보여줄 것

10개 예제의 목록과 공식 출처, 경험 원문이 있는 3개 프로그램, 저장한 원문 한 개에서 텍스트를 확보한 과정을 보여준다. 과거 원천 14만 건이나 일반 연구비 건수를 현재 서비스의 처리 완료 실적으로 사용하지 않는다.
