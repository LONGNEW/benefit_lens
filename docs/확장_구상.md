# BenefitLens 확장 구상: 근거에서 새로운 기획 초안까지

[현재 BenefitLens 범위](README.md)는 등록된 공식 기회를 찾아 실제 신청 문항에 맞는 사용자 경험 기반 초안을 만드는 것이다. 아래 내용은 기존 통합 설계안에서 보존한 후속 구상이며, 현행 제안서의 합의 범위나 구현 완료 항목이 아니다.

## 확장할 질문

지원 기회뿐 아니라 문제 근거, 공공 통계, 국내외 선행 사례, 반례, 법적 제약, 실행 자원을 모아 사용자가 새로운 정책이나 서비스 제안을 구상할 수 있게 할 것인가? 이는 신청 초안 지원과 다른 과제이므로 출처 권리, 품질 기준, 평가 지표를 별도로 정해야 한다.

```text
source_document → evidence_atom → evidence_relation
→ insight → idea_seed → draft_block
```

- `source_document`: 문서의 출처, 발행일, 이용 조건과 근거 위치를 기록한다.
- `evidence_atom`: 원문을 복제하는 대신 검증 가능한 최소 사실, 수치, 적용 범위와 불확실성을 기록한다.
- `evidence_relation`: 근거 사이의 지지, 반박, 유사점과 차이를 연결한다.
- `insight`: 여러 출처를 종합한 관찰과 해석을 분리한다.
- `idea_seed`: 해결 대상, 수혜자, 제안 행동, 차별점과 실행 자원을 적는다.
- `draft_block`: 문제, 근거, 제안, 실행, 위험과 검증 계획을 새 구조로 작성한다.

화면에서는 확인된 사실, 교차 출처 관찰, 아직 검증되지 않은 가설, 사용자 판단에 따른 제안을 구분한다. 출처 지도, 근거 카드, 반대 근거, 정보의 빈칸과 문단별 계보가 있으면 사용자가 초안을 검토할 수 있다. 권리가 불명확한 자료의 표현은 저장하거나 생성 입력으로 사용하지 않고, 허용된 사실과 링크만 다룬다. 기존 [출처와 권리 정책](../proposal/04_데이터_출처와_권리_정책.md)을 확장 분야에도 그대로 적용할 수 있는지는 별도 검토가 필요하다.

## 승격 조건

확장을 결정하기 전 실제 사용자 과제, 등록할 출처, 이용 허용 범위, 사실 추출 정확도, 원문 재현 방지와 새 초안의 평가 방식을 먼저 합의한다. 그때까지는 `README.md`의 신청 초안 범위를 우선한다.
