# BenefitLens 프로토타입 결과, 2026-09-23

> 과거 구현 기록이다. 현재 출처 범주와 화면 계약은 [회의 결론과 실행 계획](../../proposal/10_회의_결론_및_실행계획.md)을 따른다.

## 이번 단계의 질문

출처가 아직 없거나 조회에 실패한 상태를 사용자의 자격 미충족과 구분할 수 있는가? [BenefitLens 설계](../README.md)의 첫 데이터 계약을 고정 예시 레지스트리에 적용했다.

## 구현

- 당시 출처 범위 등록: 학교, 지역, 국가 세 계층을 모델링했다. 이 구현은 이후 네 범주 레지스트리로 대체돼 현재 코드에는 남아 있지 않다.
- [조회 API](../../web/app/api/opportunities/route.ts): `meta.sourceType=example-snapshot`, 출처별 상태, 연결된 예시 ID, 권리 검토 전 상태를 반환한다. 화면의 학생 입력은 서버로 보내지 않는다.
- [현재 화면](../../web/app/benefitlens/benefitlens-dashboard.tsx): 출처 계층을 선택하면 해당 출처의 예시만 판정한다. 미등록 계층의 빈 결과에는 `판정할 데이터가 없음`을 표시하고, 자격 미충족으로 바꾸지 않는다. 카드에는 예시 기준일과 현재 모집 여부 미확인을 표시한다.

## 검증 결과

| 점검 | 결과 |
|---|---|
| 타입 검사 | `tsc --noEmit` 통과 |
| Node 22 Vinext 빌드 | 통과, `/unlock`과 `/api/opportunities` 포함 |
| API 응답 | HTTP 200, 예시 6건, 학교 6건, 지역 0건, 국가 0건 |
| 서버 렌더링 | 출처 수집 범위와 예시 레지스트리 표시 확인 |
| 기존 외부 IP | `http://141.223.22.64:4173/unlock`에서 HTTP 200 확인 |

자동 브라우저 제어가 이 환경에서 제공되지 않아 출처 버튼 클릭과 프로필 입력의 시각적 상호작용은 직접 검증하지 못했다.

## 하지 않은 일과 다음 게이트

이 단계는 공식 출처 3곳의 수집 완료가 아니다. POSTECH 자료도 새로 크롤링한 것이 아니라 기존 예시이며, 게시일, 현재 공고, 조건별 원문 근거와 재사용 권한은 검증 전이다. 지역과 국가 출처의 URL 및 수집 권한도 확정하지 않았다. 신청 문항 기반 초안과 사용자 경험의 주장 계보도 아직 구현하지 않았다.

다음에는 팀이 학교, 지역, 국가의 실제 공식 출처 하나씩을 확정하고 권리 등록부를 작성해야 한다. 그 뒤 출처별 수집 실행 상태, 공고 버전, 조건별 근거를 적재하고 검토를 통과한 값만 판정 화면으로 승격한다. 미수집, 수집 실패, 조건 미충족을 API 상태로 계속 분리한다.
