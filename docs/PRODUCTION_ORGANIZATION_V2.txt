BenefitLens 대량 프로젝트의 팀 연결과 처리 기준
기준 변경: 2026-11-19

1. 무엇을 진행 상황으로 보고하는가
10개 과거 공고와 합성 프로필을 쓰는 데모는 현재 프로젝트 성과 집계에서 제외한다. 대량 수집분의 확보, 원문 연결, 구조 전처리, 의미 분석과 검토, 사용자 적용을 각각 집계한다. 사례, 문서, 문항과 수정 전후 쌍도 별도 단위로 기록한다.
2026-11-19 22:34 DB 확인에서 공고 후보는 36,856건, 경험 사례는 29,955건, 문서 테이블은 104,997건이다. 이 수량을 현재 접수 중이며 개인에게 적합한 공고나 분석이 끝난 경험으로 바꾸어 보고하지 않는다.
주 DB의 운영 정본 테이블, 대량 discovery 저장, 과거의 고정 handoff와 임시 SQL 검증 결과는 저장 계층이 다르다. 각 산출물의 실제 존재와 현재 데이터 연결을 확인하고 중복과 검증일을 표시한다.

2. 다섯 팀의 역할
T1 공고와 공유 조건: 원문, 프로그램과 회차, 모집 상태, 조건, 혜택과 공식 작성 문항을 소유한다. 공통 의미와 프로그램별 확장을 정규화하고 원문 위치와 시점을 보존한다.
T2 경험과 작성 사례: 같은 사람의 같은 사건을 여러 문서에 연결한다. 기회와 동기, 본인 역할, 선택과 행동, 결과, 성찰을 근거 구간과 함께 분해한다. 문항이 요구한 것, 지원자의 전략과 분석자의 의미 추론은 별도로 남긴다.
T3 글쓰기와 내용 검증: 교재, 공개 작성 지침, 과학 글쓰기 연구, 채점 글과 수정 전후 자료를 장르와 근거 종류에 따라 연결한다. 주장, 근거, 추론, 문단과 문서의 연결을 설계하고 작성 내용도 검토한다.
T4 개인화와 작성: T1의 조건 사전을 그대로 사용해 입력 정보, 조건별 판정과 부족한 정보를 연결한다. T2의 사례와 T3의 기준을 참고해 본인 확인 사실로 개인 작성본을 만든다.
T6 통합 운영: 수집 주기, 변경 감지, 버전, 처리 큐, 실패 복구와 팀 간 인계를 실행한다. 코드, 스키마, 데이터 연결과 회귀 검사는 이 팀이 맡는다.
기존 T5 별도 코드 평가팀은 운영팀에 통합한다. 내용 작성과 검토의 판단 기록은 구분하되, 기술 검사 수를 글의 설득력 지표로 사용하지 않는다.

3. 공고팀과 개인화팀은 같은 조건을 사용한다
공유 사전: pipeline/config/shared_condition_catalog_v1.json
조건은 field_id, 연산자, 값과 타입, 단위, 기준 시점, 근거, 검토 상태와 unknown 사유를 가진다. 개인화가 별도의 academicLevel 같은 이름으로 의미를 재정의하지 않는다.
공통 프로필은 여러 공고에서 재사용할 사용자 정보의 묶음이다. 학위, 재학 상태, 소속, 전공, 국적, 성적 등이 해당한다. 어떤 공고에서 필수인지는 해당 공고 조건과 원문이 정한다.
프로그램별 추가 정보도 같은 조건 계약으로 표현한다. 활동 시작 시점의 재학 유지, 대상 국가, 추천 경로, 중복 수혜나 특정 활동 의무를 구체적인 시점과 근거에 연결한다.
작성 재료는 조건 판정용 정보와 구분한다. 본인의 문제의식, 책임, 판단, 행동, 검증 결과와 향후 목표를 문항에 맞춰 확인한다.
원문에서 학위나 국적 표현을 발견한 단계에서는 요구 연산자, 예외나 적용 시점을 확정하지 않는다. 그 행은 후보로 남기고 개인화에서도 보류 이유를 소비한다.

4. 글쓰기 원칙 8개의 위치
기존 8개는 독자와 목적, 주제문, 문단 통일성, 구체적 근거, 연결, 근거에 맞는 결론, 간결성, 용어 일관성이다. Writing for Success와 Microsoft 스타일 가이드에서 지원서용으로 골라 편집한 요약이다.
전체 작성 근거는 교재의 명시 권고, 대학의 장르 지침, 실제 작성본과 채점, 수정 전후 관찰, 커뮤니티 조언, 실험과 관찰 연구로 구분해 보존한다. 원칙의 수를 임의로 늘리는 대신 출처, 독자, 장르, 적용 조건과 충돌 근거를 연결한다.
문단마다 목적과 주장, 근거와 추론, 첫 문장과 마지막 문장의 역할, 앞뒤 문단의 연결을 기록한다. 사용자가 요청한 문단 스타일은 공식 문항과 장르 제약 안에서 적용한다.

5. 유기적인 인계와 피드백
T1 공식 공고, 공유 조건과 문항 → T4 조건 판정과 추가 질문
T1 프로그램, 회차와 문항 → T2 관련 사례 연결 → T3 문단 전략과 기준
T3 필요한 사실과 장르 기준 → T2 경험 추출과 T4 개인 입력
T4 확인된 본인 경험 → 개인 문단 계획과 초안 → T3 내용 검토
T4의 미지원 조건과 충돌 → T1 공유 사전과 원문 재검토
T6는 이 연결 전체의 버전, 작업 큐와 실패 상태를 관리한다.

6. 코드와 실제 산출물
tools/run_benefitlens_production_pipeline.py --execute는 보존한 대량 자료의 글쓰기 근거 지도, 공고 전량 투영, 경험 전처리와 개인화 요구를 실행하고 같은 조건 사전 지문인지 검사한다. 새 웹 수집과 모델 의미 분석은 각 단계의 별도 작업으로 기록한다.
자료는 공용 캐시 team-production-20261119에 보존한다. 원문과 추출문, 문단 구간, 조건 후보, 분석 대기와 팀별 요약을 연결하고 전체 작업 큐를 만든다. 미검토 항목을 코드 실행만으로 승인하지 않는다.
초기 갱신 정책은 일반 24시간, 마감 72시간 이내 6시간, 비활성 7일이며 설정된 수시 원천은 기본 1시간이다. 정책과 제공자 요청 제한을 분리하고 변경률과 탐지 지연으로 보정한다. 기존 수집 서비스의 실제 설정과 새 정책의 연결 여부는 별도로 보고한다.
