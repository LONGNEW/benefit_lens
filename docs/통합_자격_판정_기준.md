# BenefitLens 통합 자격 판정 기준

원문은 자유문으로 보존하고 자동 판정은 표준 코드와 조건 트리로 수행한다. 현재 사전은 `eligibility-1.6.0`이며 자격 28개, 신청 후 요구사항 8개를 구분한다. 데이터 전달 필드는 [데이터 추출 계약](데이터_추출_계약.md)을 따른다.

## 어떤 조건을 비교하는가

| 영역 | 기준 |
|---|---|
| 인적 정보 | 국적, 나이, 취업 상태, 산업체 재직 여부 |
| 소속과 학적 | 학교, 학과, 현재 과정, 최종 취득 학위, 학적, 학년, 대학원 학기, Coursework, 졸업예정월, 남은 수업연한, 전일제 학생 |
| 성적과 경제 | 직전 학기 이수학점, 평점, 학자금 지원구간 |
| 지역과 기타 | 본인 및 직계존속 주민등록 지역, 거주기간, 비수도권 고교, TOPIK, 팀 인원 |
| 개별 서비스 이력 | 코드트리 유료 구매, 현재 구독, 과거 챌린지, 무료 패스 |
| 신청 후 요구사항 | 온라인 교육, 해커톤, 활동 참석, 전일 교육, 코딩 학습, 취업 준비, 카드 발급 절차, 활동 종료까지 학적 유지 |

전일제 학생은 현재 신분이므로 자격이다. 전일 교육 참석 가능 여부는 앞으로 수행할 요구사항이다. 우대는 필수 자격에서 제외한다. 제재나 중복 지원처럼 실제 제외 사유는 자격에 남긴다.

지원자에게 규정 해석을 요청하지 않는다. 원문과 연결 규정을 수집해 코드로 바꿀 수 없는 조건은 `unresolved`에 원문을 보존하고 시스템의 해석 미완료로 표시한다.

## 원문을 어떤 값으로 바꾸는가

예를 들어 `만 19~34세 대한민국 청년`은 다음 두 규칙으로 저장한다.

```text
age between [19, 34], unit=year
nationality eq KR
```

각 규칙은 기준 코드, 프로필 필드, 자료형, 연산자, 값, 단위, 원문과 출처를 갖는다. GPA 평가 기준과 지정 기간은 `context`에 저장한다. AND, OR, NOT 관계도 저장한다. `석사 1~3학기 또는 박사 Coursework 수료`는 두 지원 경로의 OR이고, 각 경로 안의 과정과 학기 또는 수료 조건은 AND다.

연산자는 `eq`, `neq`, `gte`, `lte`, `between`, `in`, `not_in`이다. 나이는 년, 이수학점은 학점, 거주기간과 남은 수업연한은 월 단위를 사용한다. GPA는 동일 척도, 동일 평가 기준과 기간에서 비교한다. 공식 4.3 또는 4.5 대안은 각각의 OR 경로로 저장한다. 만점이나 평가 기준 미상, 복수 학기 집계 미지원은 `unknown`으로 둔다. 출생연도만 있으면 가능한 두 만 나이가 모두 조건을 만족할 때 통과한다.

## 언제 통과하는가

원자 조건은 유효한 사용자 값이 있으면 `pass` 또는 `fail`, 값이 없거나 비교 단위가 불명확하면 `unknown`이다. AND는 하나라도 실패하면 실패, 모두 통과하면 통과다. OR는 하나라도 통과하면 통과, 모두 실패하면 실패다. 나머지는 미상이며 NOT은 통과와 실패만 뒤집는다.

모집 공고의 상태는 다음처럼 결정한다.

1. 기간이 끝났으면 `기간 종료`다.
2. 필수 자격이 실패하면 `조건 미충족`이다.
3. 비교에 필요한 개인정보가 비었으면 `내 정보 필요`다.
4. 필수 조건 해석이 미완료이면 `원문 보완 필요`다.
5. 접수 날짜가 미확인이면 `접수 기간 확인 필요`, 시작 전이면 `접수 예정`이다.
6. 조건과 접수 기간이 맞으면 검토 전 자료는 `조건 일치 후보`다.
7. 공고 검토 `reviewed`, 출처 권리 `approved`, 운영 허용이 모두 충족돼야 `접수 가능`이다.

참여 요구사항은 자격 트리에서 분리해 `신청하면 해야 할 일`로 표시한다. 참석 의사를 입력하지 않았다는 이유로 보류하지 않는다. 원본의 전체 조건 트리는 보존하며, 대안 경로별 의무를 완전히 표현하는 별도 요구사항 트리는 아직 없다.

상시 제도는 공개 대상 범위만 비교하고 세부 선발 기준을 함께 표시한다. 승인 전에는 `조건 일치 후보`, 승인된 대상 일치는 `제도 대상 가능`이다. 지급 확정과 모집 접수 가능은 따로 판단한다.

## DB와 사이트가 같은 결과를 쓰는가

PostgreSQL은 기준 사전, 규칙 그룹, 규칙과 미해석 원문을 저장한다. D1은 같은 버전의 조건 트리와 원문을 읽기 모델로 받는다. 실제 사용자 프로필과 비교 결과는 브라우저에서 처리하며 서버로 전송하지 않는다. `profile_snapshot`과 `evaluation` 테이블은 향후 동의 기반 기록을 위한 스키마이고 현재 웹은 사용하지 않는다.

검색은 자유문 검색과 별도로 운영기관, 혜택 태그와 모집 상태를 필터링한다. 학교에서 발견한 기업 공고도 실제 운영 주체로 검색한다.

## 확인한 구현 상태

2026년 10월 6일 재수집과 재처리 결과는 후보 73건, 자격 규칙 197개, 규칙 코드로 남은 요구사항 3개와 미해석 134개다. 서류와 활동 의무는 별도 표시 배열에 저장하므로 요구사항 코드 수가 전체 의무 수를 뜻하지 않는다. 파서 상태는 구조화 22건, 일부 구조화 44건, 검토 필요 7건이며 공개 승인 0건이다. OCR로 새로 읽은 원문도 분모에 포함한다. 원문 전체를 대조한 정확도 평가는 별도 작업이다.
