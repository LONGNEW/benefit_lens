# BenefitLens 실행 기준

이 문서는 세 가지만 정한다.

> 어디서 가져오고, 무엇을 저장하고, 언제 성공으로 보는가.

## 1. 어디서 가져오는가

| 범주 | 우선 출처 |
|---|---|
| 학교 | POSTECH 공통 장학제도, 대학원 재정지원, 전 학과 공개 지원 페이지와 CSE 전달 공고 |
| 재단 | 포스코청암재단, 미래에셋박현주재단, 일주학술문화재단 |
| 기업 연계 | 삼성꿈장학재단, SK행복나눔재단, 현대차 정몽구재단 |
| 국가 | 한국장학재단 공지, 한국장학재단 월간 학자금 데이터, 온통청년 API |

목표는 10개 기관이며 실제 수집 URL 수를 제한하는 뜻은 아니다. POSTECH은 학교 공통 제도와 공식 학과 목록 전체에서 공개 지원 페이지를 찾는다. 로그인 게시판은 우회하지 않는다. 학과당 6페이지와 깊이 2의 제한 탐색이며, 미발견을 지원 없음으로 해석하지 않는다.

출처별 상세 URL과 공개 호출 방식은 [반복 수집 출처 조사](2026-09-29_반복_수집_출처_조사.md)에 기록한다.

## 2. 무엇을 저장하는가

```text
목록 확인
→ 새 공고와 수정 공고 발견
→ 상세 페이지 수집
→ 공통 필드로 변환
→ 사용자 조건과 비교
→ 선택한 공고의 지원 초안 준비
```

공고마다 다음 정보만 우선 저장한다.

- 출처, 기관, 공식 링크
- 공고 ID, 제목, 게시일, 접수 시작일과 종료일
- 지원 대상, 학력, 전공, 성적, 소득과 지역 조건
- 지원 금액 또는 혜택
- 선발 조건, 특약과 제도 안내 또는 모집 공고 구분
- 필수 서류와 공식 신청 문항
- 각 값의 원문 근거와 수집 시각

현재는 출처의 공고 ID 또는 공식 URL에서 만든 `canonical_key`로 식별하고, 내용 변경은 새 버전으로 저장한다. 여러 게시판의 동일 사업과 모집 회차를 연결하는 상위 식별자는 미구현이다. 값이 보이지 않으면 `미확인`으로 남긴다. 실제 전달 필드는 [데이터 추출 계약](데이터_추출_계약.md)이 정본이다.

## 3. 언제 성공인가

출처 하나는 다음 조건을 모두 만족해야 완료다.

- 같은 목록에서 새 모집 회차를 다시 발견할 수 있다.
- 목록의 공고 ID와 상세 링크를 안정적으로 얻는다.
- 접수 기간과 주요 자격 조건을 원문 근거와 연결한다.
- 같은 공고를 다시 수집해도 중복이 생기지 않는다.
- 수집 실패 시 마지막 정상 데이터를 지우지 않는다.
- 세 번 연속 실행한 결과와 실패 복구 기록이 남는다.

전체 데모는 사용자가 다음 흐름을 끝내면 완료다.

1. 최소 프로필을 입력한다.
2. 검토할 공고와 제외된 이유를 확인한다.
3. 공고 하나를 선택해 공식 조건과 원문을 본다.
4. 자기 경험을 입력한다.
5. 확인된 내용만 사용한 첫 초안과 문장별 근거를 본다.

## 지금 할 일

1. 학교 전체 탐색의 미수집 경로와 이미지 및 첨부형 공고를 검토한다.
2. 세 출처에서 대표 공고를 사람이 확인해 정답 표본으로 만든다.
3. 목록 수집, 상세 수집, 중복 제거와 변경 감지를 테스트한다.
4. 통과한 뒤 나머지 출처를 같은 방식으로 추가한다.

출처별 복잡한 설명 문서는 따로 만들지 않는다. 실제 요청 방식과 필드 대응은 코드 설정과 테스트에 두고, 이 문서에는 팀이 합의해야 할 기준만 유지한다.

## 실행과 검증

`pipeline` 디렉터리에서 실행한다.

```bash
PYTHONPATH=src python3 -m data_platform.cli migrate
PYTHONPATH=src python3 -m data_platform.cli reprocess-benefitlens
PYTHONPATH=src python3 -m pytest -q
PYTHONPATH=src python3 scripts/sync_d1.py --base-url http://127.0.0.1:8790 --mode candidate --dry-run
PYTHONPATH=src python3 scripts/sync_d1.py --base-url http://127.0.0.1:8790 --mode approved --dry-run
```

`reprocess-benefitlens`는 저장 원문만 사용하며 네트워크 요청을 하지 않는다. D1 쓰기는 기존 승인된 동기화 경로 또는 로컬 일회용 writer인 `scripts/sync_local_preview.py --node <Node 22 실행 경로>`를 사용한다. 로컬 writer는 127.0.0.1에만 열리고 토큰은 메모리에서 생성한 뒤 종료한다. 웹은 Node 22로 `npm test`, `npm run build`, `tsc --noEmit`을 실행한다.

후보 조회는 `comparisonMode=demo_candidate`, 승인 조회는 `comparisonMode=approved_read`다. 현재 승인 조회는 0건이며 후보를 일괄 승인하지 않았다. 최신 실행과 남은 미수집 경로는 [10월 6일 복구 보고](../../../../tmp/2026-10-06-benefitlens-recovery-report.md)를 따른다. 웹 검증 실행은 기존 Node 24 환경을 사용했다.

## 평가 기준과 보여줄 것

| 평가 | 시연 증거 |
|---|---|
| 신규성 | 공고 발견, 자격 비교, 경험 기반 초안을 한 흐름으로 시연 |
| 효과 | 직접 검색 대비 시간, 누락, 오류를 사용자 평가에서 측정 |
| 기술 | 원본, 해시, 정규화, 버전, 품질 검사, 근거 연결을 DB와 실행 로그로 증명 |
| 발표 | 정상 수집, 중복 방지, 강제 실패, 웹 초안 순서로 시연 |

효과 항목의 사용자 비교 실험은 아직 실행하지 않았으며, 실제 결과가 생기기 전에 향상을 주장하지 않는다.
