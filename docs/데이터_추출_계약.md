# BenefitLens 데이터 추출 계약

현재 전달 계약은 `opportunity-1.1.0`, 판정 사전은 `eligibility-1.6.0`이다. 모든 수집기는 공통 중간 형식을 만들고, PostgreSQL에서 같은 공고 버전의 조건, 혜택, 서류와 문항을 D1에 복제한다. 구현 정본은 `pipeline/src/data_platform/contract.py`, `web/lib/opportunity-data.ts`와 `pipeline/scripts/sync_d1.py`다.

## 결론

BenefitLens는 공식 API 필드를 직접 매핑하고, HTML의 표와 의미 단위, PDF 변환 텍스트와 이미지 OCR 결과에 출처별 선택자, 제목 패턴과 정규식 규칙을 먼저 적용한다. `--codex`를 명시한 실행에서는 로컬 Codex가 같은 원문에서 혜택, 자격 조건, 필요 서류, 지원 문항 후보를 추가 추출한다. Codex 후보는 정본 필드를 덮어쓰지 않고 `extraction_candidate`의 `pending` 상태로 저장하며, 원문 인용이 입력 텍스트와 일치하지 않으면 폐기한다.

## 입력에서 DB까지

```text
공식 API, HTML, PDF, 이미지, HWP, HWPX
  -> 원본 바이트와 SHA-256 저장
  -> HTML 본문, PDF와 한글 문서 텍스트, OCR 텍스트 생성
  -> 출처별 구조 파서
  -> 공통 ParsedOpportunity 계약
  -> 자격 조건 표준화
  -> 선택적 로컬 Codex 후보 추출과 원문 인용 검증
  -> PostgreSQL 공고 버전, 혜택, 조건, 근거, 필요 서류, 지원 문항
  -> PostgreSQL 검토 대기 추출 후보
  -> 후보 또는 승인 전용 read model
  -> D1과 API
  -> 브라우저 자격 비교, 문항별 준비 초안
```

`ParsedOpportunity`는 제목, 설명, 공식 URL, 혜택, 자격 조건 원문, 필요 서류, 지원 문항, 근거, 기간과 화면 표시 항목을 전달하는 공통 중간 형식이다. 파서가 달라도 이 형식을 통과해야 DB에 적재된다.

## DB와 화면의 공통 항목

| 의미 | PostgreSQL | 웹 계약 |
|---|---|---|
| 공고 버전 | `opportunity_version_id`, `contract_version` | `opportunityVersionId`, `contractVersion` |
| 자격 판정 | 조건 그룹, 규칙, 값, 자료형, 단위, `context_json` | `criteria`, `rules`, `unresolvedCriteria`, 규칙별 `context` |
| 표시 구역 | `condition_sections_json` | `conditionSections` |
| 혜택 | 유형, 설명, 금액 하한과 상한, 통화, 지급 주기, 금액 한정 표현 | `structuredBenefits` |
| 준비 서류 | `required_document.document_name` | `requiredDocuments` |
| 신청 문항 | 문항 키, 원문, 제한 분량, 출처 | `applicationPrompts`, 공고 버전 ID 포함 |
| 공개 승인 | 공고 검토, 출처 권리, 운영 허용 | `publicationStatus`, `rightsStatus`, `productionAllowed` |
| 검토 이력 | `review_event`, 검토자, 사유, 대상 버전, 입력 해시 | 내부 검토 기록, 공개 권리 상태와 독립 |

표시 구역은 지원 자격, 제외 조건, 우대 조건, 요구사항, 선발과 심사, 혜택, 특약, 접수 기간, 활동 기간의 9개 배열이다. 자동 통과는 별도의 AND, OR, NOT 조건 트리로 계산한다. 참여 의사, 직무 희망, 발급 절차와 서명은 준비할 요구사항으로 전달한다. 활동내역서 제출에 붙은 대상 연도는 서류 원문에 유지한다. 나이, 과정과 제외 조건이 함께 있는 혼합 문장은 자격에서 제거하지 않는다.

GPA는 점수와 만점 외에 직전 학기, 누적 또는 지정 기간을 `context`로 전달한다. 척도와 평가 맥락이 맞을 때 비교하고, 복수 학기 집계나 미확인 척도는 미상으로 둔다. 학년 범위, TOPIK과 거주기간도 표준 기준으로 추출하며 문장에 남은 제한은 별도 미해석 조건으로 보존한다.

금액은 한 혜택 문장에 단일 화폐 표현이 있을 때만 구조화한다. `fixed`, `range`, `up_to`, `approximate`를 구분하고, 최대 또는 내외 금액은 보장 하한을 만들지 않는다. 복수 금액 요약, 등록금 비율, 물품의 상당액과 본인부담금은 숫자 필드를 비워 두고 원문을 보존한다. 혜택 문장별로 유형을 분류한다.

공식 문항은 선택한 공고의 버전 ID, 검토 상태와 출처가 일치할 때만 초안 질문으로 쓴다. 연결 자료에서 같은 문항 번호가 반복돼도 출처와 내용 기반 키로 충돌을 막는다. 공백 계산 방식이 없으면 글자 수는 참고값이며 제한 충족을 확정하지 않는다. 검토 전 문항은 추출 후보로 보여주고 일반 준비 질문을 사용한다. 현재 초안은 사용자 입력을 문항별로 정리하는 로컬 템플릿이며 LLM 생성은 연결하지 않았다.

## 후보와 승인 경로

로컬 검토 데모는 `--mode candidate`와 `comparisonMode=demo_candidate`를 명시한다. 기본 동기화는 `--mode approved`이며, `reviewed`, 권리 `approved`, 운영 허용이 모두 충족된 PostgreSQL 뷰를 사용한다. API의 `comparisonMode=approved_read`는 목록과 모든 집계에 같은 승인 조건을 적용하고, DB 연결 실패 시 예시로 대체하지 않고 503을 반환한다.

조건과 기간이 맞아도 승인 전 자료는 `조건 일치 후보`다. 승인된 모집만 `접수 가능`으로 표시한다. 원문 수집 시각과 D1 동기화 시각은 별도 필드다.

## 항목별 추출 방식

| 항목 | 우선 입력 | 현재 방식 | 실패 처리 |
|---|---|---|---|
| 혜택 | API의 지원내용, HTML의 지원내용과 혜택 구역, 표의 금액 열 | 구조 필드 직접 매핑, 제목과 본문 키워드로 혜택 유형 분류 | 내용은 원문으로 보존하고 유형은 `unknown` |
| 자격 조건 | API의 지원대상과 선정기준, HTML의 지원자격과 모집대상 구역 | 조건 문장을 수집한 뒤 정규식 사전으로 기준, 연산자, 값과 단위를 정규화 | 해석하지 못한 문장은 `unresolved` |
| 근거 | 원본 응답, 상세 본문, 연결 PDF와 이미지 | 원본 문서 ID, URL, 본문 해시와 추출 문장을 공고 버전에 연결 | 수집 실패 상태와 오류를 별도 기록 |
| 필요 서류 | 첨부파일 이름, 제출서류 구역, 신청서와 증명서 문장 | 문서 확장자와 제출서류 키워드 규칙으로 추출 | 없으면 빈 목록, 존재하지 않는다고 확정하지 않음 |
| 지원 문항 | 지원동기, 자기소개, 학업계획, 활동계획, 서술문항 구역 | 문항 문장과 글자 수를 정규식으로 추출하고 선택 실행 시 Codex 후보를 추가 | 원문 인용 일치 후보만 `pending`으로 저장 |
| 참여 조건 | 활동 일정, 참석 의무, 교육 기간과 장소, 중복과 반환 조건 | 의미 구역과 조건 키워드로 화면 표시 항목과 판정 조건을 분리 | 자동 판정 불가 문장은 설명 항목으로 유지 |

## 파일 형식별 처리

### 공식 API

API가 제공하는 정책번호, 기관, 지원내용, 지원대상, 선정기준, 신청기간과 신청 URL을 필드 이름으로 직접 매핑한다. 필드 의미가 명시돼 있으므로 자유 텍스트 분류보다 우선한다.

### HTML

출처별 CSS 선택자와 표 헤더를 먼저 사용한다. 공통 상세 파서는 지원 내용, 지원 자격, 제출 서류, 참여 조건, 특약과 기간 제목을 찾아 인접 문장을 가져온다. 공개 초기 응답의 JSON-LD 또는 내장 본문도 읽는다. 본문이 없는 페이지는 실패로 기록한다. 내비게이션, 광고와 푸터는 제외한다.

### PDF

원본 PDF를 저장한 뒤 `pdftotext -layout`으로 텍스트를 만든다. 추출된 텍스트는 HTML과 같은 의미 구역 규칙으로 처리한다. 텍스트가 지나치게 짧으면 자동 추출 실패로 기록한다.

### 이미지

`tesseract`의 한국어와 영어 모델로 OCR한다. OCR 결과는 `ocr_review` 상태, 원본 이미지 URL, 원본 문서 ID와 함께 보존한다. 선택적 Codex 단계는 OCR 텍스트와 DB에 저장된 원본 이미지를 함께 받아 문항과 조건 후보를 분류한다. 이미지 입력은 `include_ocr_images` 설정으로 끌 수 있다. 후보의 인용문이 OCR 텍스트에 없으면 저장하지 않으며, 저장된 후보도 원본 이미지 대조 전에는 `pending`이다.

문서 형식은 URL뿐 아니라 MIME, 다운로드 헤더와 파일 시그니처로 결정한다. OCR은 명시한 실행 명령, 시스템 도구, `config/document_tools.json`의 검증된 로컬 실행환경 순으로 찾는다. 한국어와 영어 모델을 확인하고 이미지 변환 subprocess에만 라이브러리 경로를 전달한다.

### HWP와 HWPX

HWP는 설치된 `hwp5txt`로 변환한다. HWPX는 크기 제한을 적용한 ZIP과 XML 본문을 읽고 외부 엔터티와 과도한 압축 확장을 차단한다. 변환기 부재, 보호 문서 또는 읽을 본문이 없으면 실패 원인과 원본 ID를 남긴다. 학교 탐색은 PDF와 HWPX 다운로드 링크도 발견 대상으로 포함한다.

## 로컬 Codex 보조 단계

수집 프로세스는 로그인된 로컬 `codex exec`를 읽기 전용 샌드박스와 임시 세션으로 실행한다. 최종 응답은 `benefitlens_extraction.schema.json`으로 제한하며, 항목 종류, 공고 번호, 원천 번호, 제안값, 원문 인용, 신뢰도, 글자 수 제한을 모두 필수로 요구한다. 모델명과 프롬프트 계약 버전은 후보 행에 저장한다.

Codex 후보는 정규식 결과와 별도 저장한다. `review-packet`은 현재 버전의 검토 입력을 만들고 `review-benefitlens`는 원문 인용, 버전 해시, 기준 변환과 검토 사유를 검증한다. 기본은 검증만 수행하며 `--apply`로 명시한 승격, 반려 또는 검토 결정을 저장한다. 승격은 새 공고 버전을 만들고 후보 결정과 `review_event`를 남긴다. 금액 후보의 자동 승격은 미지원이다.

공고 검토 완료에는 원문 대조 확인, 미해석 조건 없음과 실패 자료 없음이 필요하다. OCR 자료는 원본 이미지 대조 확인을 추가로 요구한다. 검토 도구는 출처 권리와 운영 허용을 변경하지 않는다. 동일 내용 재수집은 현재 버전만 중복으로 처리하고, 다른 버전을 거쳐 같은 내용으로 복구되면 새 유효 구간을 만든다.

기본 수집은 Codex를 실행하지 않는다. `--codex`를 지정한 실행만 로컬 로그인 세션을 사용하며, 지원 문항 탐색 대상인 `notice`와 OCR 원천을 여러 건씩 묶어 분석한다. 구조화 API와 정규식으로 충분히 처리된 `policy`는 OCR 원천이 없으면 생략한다. 한 실행의 최대 공고 수, 배치 크기, 공고별 최대 입력 글자 수와 OCR 이미지 수를 설정으로 제한한다. 파이프라인은 별도 API 키를 읽거나 저장하지 않는다.

## 현재 한계

- 정규식 지원 문항은 제목이 명시된 문장만 찾기 때문에 표 안의 문항이나 별도 신청서 내부 문항을 놓칠 수 있다. Codex 후보가 이 범위를 보완하지만 승인 전에는 공개 데이터가 아니다.
- HWP와 HWPX 변환은 구현 및 회귀 검증했고, 실제 출처별 첨부 형식과 내용의 완전성은 별도 검토한다.
- 범용 학과 파서는 지원 금액과 장학 키워드 중심이라 출처별 전용 파서보다 정확도가 낮다.
- 2026년 10월 4일의 70건 집계는 과거 실행 기록이다. 10월 6일 재수집, 재처리와 웹 반영 결과는 [복구 보고](../../../../tmp/2026-10-06-benefitlens-recovery-report.md)를 따른다. 별도 `/academic` 문항 자료는 메인 후보 집계에 포함하지 않는다.
- 저장 자료 재처리는 기존 원본과 수집 시각을 유지한다. 새 수집은 별도 실행과 원문을 추가하며 각 시각을 동기화 시각과 구분한다.
