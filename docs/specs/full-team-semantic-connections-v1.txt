BenefitLens 전량 의미 분석과 팀별 연결 v1
기준일: 2026-11-20, Asia/Seoul

실행 경로
공고와 경험의 문맥 묶음 전체를 분석하고, 검증된 결과를 공유 필드와 원문, 질문 경로, 사례, 실제 문단 구조와 작성 기준으로 연결한다. 반복 표현의 대표 문맥을 직접 읽은 수와 같은 문맥에 코드를 적용한 수는 나눠 집계한다.

실행 서비스
1. benefitlens-codex-corpus-20261120.service
청크당 최대 100개, 동시 4개, 대기 큐 전체가 대상이다. 실제 CLI 이벤트, 요청, 응답과 영수증을 보존한다. 검증 통과에는 무관한 문맥으로 분류한 결과도 포함한다.
2. benefitlens-paragraph-patterns-20261120.service
완전한 원문 문단과 바로 앞뒤 문단을 최대 20개씩 두 청크로 분석한다. 입력 예산은 160,000자이며 큰 입력은 나눠 처리한다. 모델은 목적, 문장 역할, 주장, 근거, 추론, 첫 문장과 마지막 문장, 앞뒤 문단의 관계를 해석한다. 코드는 근거 구절의 유일한 위치를 원문에서 계산하고 검증한다.
3. benefitlens-team-handoff-20261120.service
10개 완료 배치 또는 1,000개 해석 증가, 원천과 코드 변경, 새 문단 분석 완료, 공급자 대기와 마지막 큐 소진을 감지한다. 일반 감시 간격은 30초다. 매 갱신에서 8단계 결과와 파일 해시를 보존하고 최대 2쪽 보고서를 생성한다.

팀 인계 순서
compact_handoff → source_links → experience_quality → personalization → writing_registry → condition_schema_links → writing_pattern_links → operations
상위 의존성이 실패하면 해당 연결 단계를 건너뛰고 실패 원인을 보고한다. 원천 분석 워커는 계속 독립적으로 실행된다.

공통 스키마 연결
semantic-connections/conditions/conditions.sqlite에 catalog_fields, analyzed_groups, documents, candidate_sources, occurrences, mappings, source_bindings, requirement_routes를 연결한다. condition_schema_links 뷰에서 모델 해석, 원문, 공통 필드 또는 프로그램별 키, 주체, 시점과 질문 경로를 조회한다.
공유 카탈로그의 19개 필드 중 공통 필드와 program_specific.requirement를 구분한다. 조건의 값 추출 계획을 실행 가능한 개인 자격 판정으로 바꾸려면 별도 값과 논리 검토가 필요하다. 현재 관계 연결은 unreviewed, executable=0이다.

경험과 작성 패턴 연결
semantic-connections/writing/links.sqlite3에 실제 해석 관찰과 원문 위치, 문단, 사례를 연결하고 완전한 문단 입력을 버전별 tasks로 보존한다.
patterns.sqlite3는 문단 전체의 실제 모델 실행과 검증 결과를 저장한다. 각 청크는 요청 해시, 스키마, 원문 해시, 실제 완료 이벤트와 결과 영수증을 갖는다.
writing_pattern_links 단계는 완료된 결과를 다시 대조한 뒤 pattern_connections와 semantic_criterion_links에 저장한다. 문단 분석 → 기존 경험 문맥 → 원문 구간 → 문단 → 사례의 연결과 모델이 수행한 기준별 평가를 조회할 수 있다.
공식 문항과 모집 회차가 확인되지 않은 결과는 일반적인 작성 구조로 한정한다. 현재 다른 사람의 사례에서 관찰한 논리 구조이며, 사용자의 개인 사실이나 입증된 합격 효과가 아니다.

보고의 완료 단위
공고팀: 실제 모델 해석 그룹, 그중 관련 그룹, 원문과 공유 필드 연결 매핑, 공통 필드와 프로그램별 키의 분포.
경험팀: 실제 관련 의미 해석, 검증된 원문 구간, 문단과 사례까지 연결한 고유 그룹.
작성팀: 문단 전체 실제 LLM 분석, 재검증 후 관계 테이블에 저장한 분석, 사례 연결과 기준 평가 연결.
개인화팀: 원문과 같은 field_id로 연결한 질문 경로. 실제 사용자 질문과 자격 판정은 별도 집계한다.
운영팀: 실제 완료 단계, 실패와 의존성 보류, 상위 분석과 파생 연결의 시차.
후보 재고, 단순 키워드 검출, 전처리 구간, 자료 역할 배정 수를 의미 분석 완료량으로 더하지 않는다. 실행 중과 공급자 대기, 보류를 나누고, 미측정은 0으로 바꾸지 않는다.

저장과 운영
공용 캐시의 team-production-20261119/team-expansion-20261120 아래에 결과를 보존한다. 원문은 기존 공용 캐시를 재사용하고 임의로 이동하거나 삭제하지 않는다.
경험 품질 SQLite는 WAL로 갱신해 읽기 스냅샷과 새 저장이 충돌하지 않게 한다. 실제 원문 변경은 새 입력 버전으로 남기고 완료한 이전 입력은 다시 호출하지 않는다.
공급자 한도와 인증 오류가 관측되면 추가 요청을 멈추고 이유를 보존한다. 명시적으로 재개할 때 공급자 오류로 실행하지 못한 입력만 해제하고 성공한 형제 입력은 재사용한다.

테이블의 용도
기존 benefitlens.experience_fact는 사용자가 제공한 개인 사실을 저장하며 동의와 보존기간 계약을 따른다. 공개 후기의 저장 대상으로 사용하지 않는다. 공개 경험과 문단 패턴은 위의 출처 연결 관계 테이블에 저장한다.
