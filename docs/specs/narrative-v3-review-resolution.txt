문단 전술 v3의 검토와 반영, 2026-11-20

변경
연구 제안서를 상황과 문제, 요구와 과제, 본인 기여와 확인 범위, 남은 문제와 준비, 다음 연구와 의의로 구성했다. 과제 문단은 한 개 이상 반복하며, 각 과제가 충족할 요구를 따로 기록한다. 문단 사이에는 앞 문장의 내용을 받는 지시어와 해당 슬롯을 저장한다.

Claude 검토
로컬 Claude CLI로 초기 양식과 수정 양식을 각각 검토했다. 검토 입력과 응답, 사용 기록은 로컬 실행 폴더 narrative_v3_20261120/calls의 claude-narrative-v3와 claude-narrative-v3-resolution에 남겼다.

수용한 지적
1. 반복 과제마다 해결 요건을 지정했다. task_bindings는 과제별 행동, 상태, 근거 슬롯과 공통 해결 요건을 연결한다.
2. 진행 문단에서 같은 확인 범위를 다시 쓰던 마지막 문장을 남은 질문으로 바꿨다.
3. 기여 진술서와 실행 제안서에도 행동이나 준비 근거가 없는 문단을 보완 질문으로 바꾸는 처리를 적용했다.
4. 공개 배경을 채울 때 출처 ID를 요구하고 문장에 출처를 표시한다. 공개 자료는 본인의 관찰과 행동 슬롯에 넣을 수 없다.
5. 양식과 전략이 편집상 설계라는 출처 표시를 각각 저장했다.

검토 판단을 조정한 부분
첫 검토에 단일 연구 양식의 계약만 제공해, 다른 장르와 두 과제의 계약이 없는 것으로 해석되었다. 생성 함수는 모든 장르와 반복 과제의 계약을 만든다. 원문 확보 없이 새 출력 폴더에 과제 두 개를 생성해 task_bindings 두 개와 공통 성공조건 연결을 확인했다.

진행 중인 과제의 중간 관찰을 모두 ongoing으로 바꾸라는 제안은 그대로 적용하지 않았다. 진행 중인 행동은 ongoing, 이미 확인한 중간 관찰은 completed로 구분한다. 앞으로 확인할 결과를 현재 관찰에 넣으면 검사가 거부한다.

기계 검사는 문단 간 참조와 출처, 시제의 일관성을 다룬다. 요구에서 과제의 필요가 도출되는지와 기존 기여가 다음 연구의 준비가 되는지는 문맥 검토 항목으로 남겼다.

검증
전체 Python 테스트 1,512개 통과. 개별 하위 검사 10개도 통과했다. 실제 초기 초안은 다섯 문단으로 다시 조립했다. 원문 근거 연결, 문단 간 참조와 DB 외래키 검사에서 오류가 없었다. 과제 한 개부터 세 개까지 생성하고, 본인 기여 근거가 없을 때 질문을 반환하는 동작을 검사했다.
