BenefitLens 완료 자료의 공개 탐색과 공고 갱신 계약 v1

1. 사용 자료
공고 열람은 원본 파일, 추출 텍스트와 식별 정보의 검증이 끝난 행을 사용한다. 개인 자격 판단은 별도 상태다. 경험은 분석 완료, 관련 판정과 원문 답변 구간이 확인된 조각을 사용한다. 미처리, 파싱 실패, 원문 불일치와 원문 근거 밖의 조각은 공개 자료집에서 제외한다. 이전 처리 원장은 재개와 재현용으로 보존한다.

2. 개인화 이전과 이후
공개 탐색은 개인 정보 없이 키워드, 분야, 국가와 지원 유형으로 후보를 찾는 과정이다. 현재 독립 CLI는 키워드와 기록된 국가 검색을 실행한다. 국가가 없는 자료는 국가 조건 일치로 추정하지 않는다. 개인화는 학교, 학위, 재학, 전공 등으로 해당 공고의 자격을 확인하고 부족한 정보만 묻는다. 관심과 자격은 별개이며 공고 열람에 재학증명서나 성적증명서를 요구하지 않는다.

3. 경험 재료
원천 점유율로 자료 수를 제한하지 않는다. 같은 질문에 서로 다른 답을 쓴 자료는 유지한다. 정규화한 질문과 답변이 완전히 같은 경우에만 내용 ID를 공유하고 사례별 출처는 보존한다. 서로 다른 사람의 비슷한 주장을 동일 사건으로 병합하지 않는다. 질문, 메뉴와 평점은 경험의 성과로 취급하지 않는다. 참여 후기, 지원 과정, 작성본과 조언의 용도를 구분해 검색한다. 선정 결과는 별도 확인이 있는 경우에만 사용한다.

4. 갱신 주기
기존 notice_refresh_policy_v2.json을 적용하는 운영 계약이다. 기본 24시간, 마감 72시간 이내는 6시간, 선착순과 예산 소진은 1시간, 마감 자료는 7일이다. 원천의 요청 제한과 Retry-After가 더 늦으면 원천 시각을 따른다. 주기는 2~4주간 변경 빈도와 탐지 지연, 요청 비용을 관찰해 조정한다.

5. 신규와 기존의 두 경로
신규 공고는 등록된 목록, 공식 API 또는 피드의 마지막 처리 지점을 이어 읽고 원문 URL을 확인한다. 재수집 목록을 주기적으로 비우고 다시 시작하지 않는다. 기존 공고는 next_check_at 순으로 확인하며 ETag 또는 Last-Modified가 제공되면 조건부 요청한다. HTTP 304는 마지막 확인 시각만 갱신한다. 변경 여부는 원문 해시와 본문 해시를 구분한다.

6. 변경 처리
공고 ID와 원천 ID는 유지하고 raw_sha256, text_sha256, fetched_at으로 새 원문 버전을 만든다. 본문이 같으면 이전 분석을 재사용한다. 본문이 달라지면 조건, 요구 서류와 문항을 재추출하고 해당 버전을 검사한다. 새 버전이 준비되기 전에는 이전 결과를 최신 판단으로 표시하지 않는다. 재검사가 끝난 버전만 공개 조회에 교체한다.

7. 중복과 상태
동일 기업, 동일 직무의 국가별 링크는 지원 단위가 같으면 하나로 연결한다. 다른 모집 회차와 다른 신청서는 구분한다. 접수 중, 마감과 재공고는 원문의 명시 상태 또는 공고 회차의 검증된 신청 기간으로 판단한다. 통신 실패, 403과 파싱 실패를 마감으로 바꾸지 않는다. 최신 모집 확인이 필요한 조회에서는 검증 시효가 지난 자료를 제외한다.

8. 개인 결과와 초안
조건이나 문항 버전이 바뀌면 영향을 받는 개인 판정, 부족 질문과 작성안을 재검토 대상으로 기록한다. 제출 전에는 선택 공고의 최신 원문과 필수 문항을 다시 읽는다. 과거 후기와 작성 양식은 해당 문항의 현재 요구에 맞춰 선택한다.

9. 실제 경로와 적용 범위
benefitlens_completed_catalog.py가 검증된 원문 view와 완료된 구절 큐를 읽어 새로운 SQLite 자료집을 만든다. --build 후 --query로 개인 정보 없이 검색할 수 있다. 이 자료집은 기존 웹 서비스의 자동 배포를 변경하지 않는다. 일일 신규 발견과 재확인 실행 서비스의 연결은 위 운영 계약에 따라 별도로 적용한다. 갱신 설계와 실제 네트워크 실행 실적은 구분해 기록한다.
