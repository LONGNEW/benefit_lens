BenefitLens 전량 처리와 팀 확장 v1
기준일: 2026-11-20, Asia/Seoul

범위
DB의 공고 후보 36,856건과 경험 30,660행을 확인했다. 과거 데모 14행을 뺀 경험 생산 범위는 30,646건이며, 연결 문서는 31,299개다. 이전 스냅샷 이후 추가된 경험 705건을 반영했다. 비활성이나 병합 기록은 보존하고 반복 의미 분석을 피한다.
보존 원문에서 추출한 공고와 경험의 문장 또는 문맥 묶음 268,925개를 처리 큐에 넣었다. 원문이 없는 공고 10,821건은 별도 확보 작업으로 남긴다. 본문 확보, 구조 전처리, LLM 해석, 원문 연결, 내용 검토와 개인 적합성은 서로 다른 상태다.

전체 의미 해석
도구: tools/run_benefitlens_codex_corpus.py
실행: python3 tools/run_benefitlens_codex_corpus.py --batch-size 100 --concurrency 4 --max-input-characters 160000 --timeout 900 --reasoning-effort low
실제 서비스: benefitlens-codex-corpus-20261120.service
max-batches를 지정하지 않아 대기 큐 전체가 대상이다. 공고와 경험을 번갈아 처리하고, 실제 CLI JSONL 이벤트, turn.completed 사용량, 최종 JSON과 원문 연결을 저장한다. 이전에 끝난 해석과 같은 문맥은 재사용한다.
2026-11-20 07:48 KST부터 이전 50개 순차 호출을 100개 청크, 동시 4개 호출로 교체했다. 원문과 프롬프트가 문자 예산을 넘으면 청크를 줄이고 나머지는 대기에 유지한다. 모델 호출만 병렬이며, 큐 선점과 검증 결과 저장은 한 조정자가 맡는다. 청크 실행 상세는 docs/specs/chunked-corpus-execution-v2.txt를 따른다.
사용자의 시간과 비용 요구에 따라 일괄 분류의 추론 설정을 low로 사용한다. 기존 모델명과 전역 사용자 설정은 바꾸지 않는다. 구문과 원문 검증이 실패한 그룹만 보류하고 전체 배치를 재호출하지 않는다.
원문 스키마는 보존한다. 공급자가 받지 않는 allOf, if, then, else와 uniqueItems 등은 전송용 사본에서만 조정하고 로컬 원본 검증기를 실행한다. 실제 API 실행 전 실패한 요청과 모델이 완료한 요청을 구분한다.
작업 중단 후에는 보존된 실제 출력과 영수증을 먼저 복구해 같은 입력의 중복 호출을 막는다. 사용 한도와 인증 문제가 발생하면 추가 요청을 멈추고 이유를 남긴다. 분석 서비스 실행 상태와 남은 큐는 따로 기록한다.

원문 증분
도구: tools/run_benefitlens_compact.py scan --kinds experience --source-root <새 스냅샷>
새 자료는 기존 dataset을 덮어쓰지 않고 날짜별 입력을 보존한다. 원문 ID, 텍스트 해시, 구간과 역할로 기존 원문 연결을 재사용한다. 같은 구간 번호를 가진 새 텍스트 버전은 따로 보존한다. 짧은 SQLite 쓰기 구간을 사용해 추론 결과 저장과 충돌을 줄인다.
최신 경험 스냅샷: team-expansion-20261120/source-refresh-20261120/experience
문서의 이전 버전 경로는 compact/queue.sqlite의 document_sources에서 참조한다.

팀별 확장
공고와 스키마: 공유 19필드와 프로그램별 요구를 실제 표현에 연결한다. 자격, 우대, 제출 자료, 혜택 설명과 활동 의무를 구분하고 주체와 시점을 보존한다.
경험 품질: 원문 구조에서 본문, 메뉴, 추천글과 쿠키 구역을 분리한다. 검증한 원문 위치를 유지하며 application의 소프트웨어 의미 같은 동음 표현 후보를 구분한다. 단순 키워드가 본문에 있다는 이유로 삭제하지 않는다.
좋은 글과 작성: 기존 987,071개의 혼합 근거 행을 자료 역할과 장르별로 연결한다. 공식 문항의 의도, 주장, 근거, 추론과 문단의 연결을 registry로 제공한다. 자료의 원래 채점 척도와 성공 여부의 근거를 보존한다.
개인화: 실제 공고 매핑의 대상과 필수 여부, 시점에 따라 공통 입력, 프로그램별 질문, 기관 정보와 작성 재료를 구분한다. 본인의 확인된 사실을 받기 전에는 다른 사람의 경험으로 빈칸을 채우지 않는다.
통합 운영: 모든 공고에 대해 중복 URL을 묶은 35,668개 재확인 작업을 생성했다. 초기 정책은 일반 24시간이며 명시된 마감과 모집 방식이 확인되면 별도 정책을 적용한다. 이 목록은 계획이며 새로 수집한 공고 수가 아니다.

팀 연결과 보고
도구: tools/run_benefitlens_team_handoff.py --watch --batch-interval 25 --with-pdf
25개 실제 완료 배치마다, 원문 스냅샷이 바뀌거나 처리 서비스가 종료할 때 인계, 원문 검사, 경험 품질, 개인화, 작성 registry와 운영 자료를 갱신한다. 이 coordinator 자체는 모델을 호출하지 않는다.
구조 처리는 문서와 사례, 설정, 전처리 버전이 같으면 기존 구역을 재사용하고 새 해석과 연결 상태를 갱신한다. 글쓰기의 큰 근거 지도도 지문이 같으면 재분류하지 않는다.
스냅샷마다 시작과 종료 큐 상태, 단계별 성공 또는 실패, 불변 summary 사본과 해시를 남긴다. Python 보고서 도구가 최대 두 페이지의 현황 PDF를 생성한다. 전량 처리 중과 대기 소진, 보류 잔존을 구분한다.

중요한 경계
문맥 묶음을 해석한 수는 원서 전체나 사람을 분석한 수와 다르다. 코드 재사용으로 연결한 문장 수와 모델이 직접 읽은 대표 문장 수도 나눈다. 글쓰기 근거의 문서, 게시물, 채점 관찰과 수정 쌍은 사람 수로 합산하지 않는다.
문단의 첫 문장과 마지막 문장의 연결은 사용자 스타일 선호다. 실제 원문 경계는 구조 근거와 함께 표시하고, 물리적 앞뒤 순서를 논리 관계로 확정하지 않는다. 조건이 불명확하면 개인 적합성을 확정하지 않는다.
