경험 구절의 압축 해석 계약

tools/benefitlens_compact_experience.py는 문서 전체 심사를 실행하지 않는다. 부모 코드가 원문을 문장과 문단으로 나누고 저장하며, 이 모듈은 관련 구절의 후보 태깅과 안전한 그룹 키, 짧은 LLM 배치 입출력을 제공한다. 크롤링, 모델 호출, DB 쓰기는 하지 않는다. 이전 분석 모듈과 스키마, 모델 원 출력도 수정하지 않는다.

1. 코드 후보와 그룹
tag_passage(passage)는 원문 위치를 검사한 후 None 또는 tags와 tag_hits를 붙인 occurrence를 반환한다. 필수 입력은 passage_id, document_id, text_sha256, char_start, char_end, text다. context_start, context_end, context_text가 있으면 원문 부분 문자열이 정확히 일치해야 한다. case_key, source_url, source_role, genre, sentence_index, paragraph_position도 보존한다.

후보 태그는 동기, 상황, 본인 역할, 선택, 행동, 결과, 성찰, 향후 활용, 지원 과정, 작성 조언이다. 태그는 관련 단어의 검출 결과다. 각 hit에는 원래 문서의 문자 위치와 실제 표현을 기록한다. 이메일 머리글, 발신 정보, 페이지 식별자, 독립 제목과 탐색 메뉴는 제외한다. 이메일 주소가 등장해도 본인 행동이 있는 서술문은 유지한다.

group_key(occurrence)는 text와 context_text, source_role, genre를 기준으로 만든다. 공백과 Unicode 정규화만 적용하며 숫자, 부정어, 문장부호와 대소문자를 보존한다. 같은 문장이라도 문맥이나 자료 역할이 다르면 나눈다. 부모 SQLite는 이 키로 groups와 occurrences를 연결할 수 있다. group_candidates는 작은 입력을 위한 메모리 도우미다.

2. 짧은 모델 입력
build_batch(groups, max_context_characters=900)는 group_id, representative, occurrence_count, source_refs가 있는 그룹들을 받는다. 부모가 30~50개 그룹을 모아 한 번에 호출한다. 모델에는 그룹 ID와 짧은 원문 문맥, 초점 위치, 후보 태그, 문단 위치, 자료 역할을 보낸다. 긴 입력은 선택 창의 위치와 focus_complete_in_view, context_complete_in_view를 남긴다.

result_schema()는 groups 배열을 요구한다. 그룹별로 relevance, event_roles, actor, writing_move, material_role, claim_evidence_reasoning, opening_or_closing_function, local_connection, limits, support_quote를 반환한다. 부재 정보는 null로 둔다. 페이지와 양식의 물리적 순서를 의미 연결로 강제하지 않는다. 지원서가 아닌 공개 후기에서 미공개 지원서의 구조를 만들지 않는다.

source ID와 긴 원문 인용은 모델에 다시 쓰도록 요구하지 않는다. support_quote는 선택 사항이며 null을 허용한다. 원문 연결은 코드가 대표 passage와 source_refs로 붙인다. 인용이 있으면 제출한 짧은 문맥에서 위치를 검사하고, 비대표 occurrence의 인용까지 검증했다고 표시하지 않는다.

3. 부분 검증과 집계
validate_group(row, group)는 그룹 한 개를 검사한다. validate_result(result, batch, allow_partial=True)는 정상 groups를 유지하고 누락, 중복, 잘못된 ID, 형식 오류가 있는 그룹만 unresolved_groups에 남긴다. relevance=uncertain은 annotation을 보존한 semantic_uncertain 상태로 둔다. 자동 모델 재호출은 하지 않는다. allow_partial=False는 전체 미해결 목록을 오류로 반환한다.

집계는 requested_passage_groups, interpreted_passage_groups, linked_occurrences, linked_unique_source_sentences, uncertain_passage_groups를 나눈다. 원문 문장 식별키는 document_id, text_sha256, sentence_index다. 같은 문장에서 여러 표현 span을 얻어도 문장 수는 한 번 센다. 해석 범위는 visible_passage_only와 selected_occurrences_only이며 문서와 사례 전체의 분석 완료 건수는 0으로 남긴다.

tools/tests/test_benefitlens_compact_experience.py의 12개 경계 테스트가 통과했다. 원문 위치, 메타데이터 제외, 안전한 그룹화, 긴 입력의 선택 창, 인용의 선택적 검증, 문제 그룹의 부분 보류, 원문 문장과 표현 출현 수의 분리를 검사했다. 실제 모델 효율은 부모의 최초 1~2회 배치에서 입력량, 해석 그룹과 연결 원문 수로 확인한다.
