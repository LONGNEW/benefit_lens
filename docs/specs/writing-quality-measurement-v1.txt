글 품질 측정과 비LLM 진단 계약 v1
기준: 2026-11-20. 구현 범위는 명시 주석의 기계 진단과 제공된 두 사람 평가의 집계다. 의미 품질, 설득력과 선정 효과는 측정하지 않는다.

1. 기존 평가표와 검토 순서
writing_quality_rubric_v1의 9항목은 문항 대응, 본인 역할, 근거, 추론, 문단 목적, 문단 연결, 프로그램 적합성, 실행 계획과 표현을 진단하는 순서 척도다. 0/1/2의 합계나 합격선을 정의하지 않았다. 미관찰과 해당 없음은 null이다.
writing_evidence_framework_v2의 6단계는 요구 → 주장 → 근거 → 추론 → 문단 → 문서다. 각 판단을 원문과 연결하는 검토 순서이며 6점 척도가 아니다. 새 자동 진단값을 기존 9항목의 점수에 더하지 않는다.

2. 함수와 CLI
도구: tools/benefitlens_writing_diagnostics.py
설정: pipeline/config/writing_nonllm_checks_v1.json
함수:
diagnose_writing(payload) → 진단 결과 dict. 입력을 변경하지 않는다.
quadratic_weighted_kappa(ratings_a, ratings_b, categories=(0,1,2), minimum_pairs=2) → 순서가 고정된 두 수열의 산술 집계. 사람 평가라는 주장은 하지 않는다.
aggregate_human_reviews(rows, categories=(0,1,2), minimum_pairs=2, document_provenance='unknown') → 출처를 선언한 사람 평가만 기준별로 묶는다.
저장소 루트의 실행:
python3 tools/benefitlens_writing_diagnostics.py --input INPUT.json --output RESULT.json
python3 -m pytest -q tools/tests/test_benefitlens_writing_diagnostics.py
CLI는 UTF-8 JSON의 실제 바이트 해시와 정규화 입력 해시, 설정 해시를 결과에 남긴다. 출력은 공백을 압축한 JSON이다. 10,000자를 넘으면 분할 입력을 요청하고 파일을 쓰지 않는다. 모델, 네트워크, 서비스와 DB를 호출하지 않는다. 외부 출처 경로나 URL을 자동으로 읽지 않는다. 코드와 입력 파일의 해시는 실행 묶음에도 보존한다.

3. 입력 계약
최상위 document_id, provenance, subject_id, allowed_experience_ids, text는 대상과 원문을 식별한다. 다음 목록은 선택 사항이며 없으면 해당 검사를 미관찰로 둔다. 목록을 제공할 때 객체 ID는 비어 있지 않은 고유 문자열이어야 한다. 잘못된 목록 형식과 중복 ID는 ValueError로 거부한다.
paragraphs: paragraph_id, sentence_ids. 목록 순서가 실제 문단 순서다.
sentences: sentence_id, paragraph_id, text, fact_ids. 주체 검사를 하려면 subject_id와 experience_id, 계획 검사를 하려면 claim_kind를 제공한다. 지원 kind는 observation, performed_action, result, state, future_plan이다. activity_status는 completed, ongoing, planned를 지원하고 사실과 문장의 명시 상태를 비교한다. state에는 as_of와 state_value가 필요하다. literal_fact_binding=true는 단일 사실 문장의 문자 보존을 요구할 때만 사용한다.
facts: fact_id, subject_id, experience_id, kind, status, value, as_of와 source_ref. confirmed는 호출자가 확인했다고 선언한 상태이며 진위 인증 결과가 아니다.
sources: source_id, text, sha256. source_ref의 source_id, char_start, char_end와 quote는 해당 원문에서 구간을 가리킨다. 선택 항목 text_sha256이 있으면 해당 사실이 참조하는 원문 해시도 비교한다. 구간은 유니코드 문자 기준, 해시는 UTF-8 바이트 기준이다. evidence_id만 있고 원문과 구간이 없으면 구간 검사를 수행하지 않는다.
claim_ground_links: link_id, claim_sentence_id, fact_ids. 연결 대상의 존재만 검사하고 지지 관계의 타당성은 판정하지 않는다.
requirements: requirement_id, required, applicable, sentence_ids. required=true이지만 기존 문장과 연결되지 않은 경우를 진단한다. 이 명시 주석은 의미 대응 정답이 아니다. 공식 문항 여부와 적용 범위는 호출자가 별도로 검토해야 한다.
paragraph_links: link_id, from_paragraph_id, to_paragraph_id, from_sentence_id, to_sentence_id. 끝점과 문단 소속, 선언한 다음 문단이 실제 순서에서 인접하는지 확인한다.
outline_order: basis와 expected_paragraph_ids. 기대 목록이 비어 있으면 강제 순서가 없다. 값이 있으면 전체 문단 순서와 정확히 비교하며 공식 순서, 사용자 지정과 합성 기대 순서를 basis로 구분한다.
constraints: max_characters, max_words, max_paragraphs, max_pages. 문자 수는 공백과 줄바꿈을 포함한 유니코드 문자, 단어 수는 공백 분리 기준이다. 지원하지 않는 계산법과 렌더링이 필요한 페이지 수는 미관찰이다.
tasks: task_id, depends_on, start, end. 명시한 의존 그래프의 순환, 없는 선행 작업, 종료일 역전과 선행 작업 종료 전 후속 작업 시작을 검사한다. 같은 날짜의 종료와 시작은 허용한다. 날짜는 YYYY-MM-DD 또는 시간대가 있는 ISO 시각이다. 날짜와 시각의 서로 다른 정밀도, 시간대 없는 시각은 추정하지 않는다.
human_reviews와 annotation_provenance는 사람 기록과 주석 작성 경로를 담는다. 사람이 준 정답 주석을 모델이 추출한 결과로 표시하지 않는다.

4. 출력과 분모
checks의 각 항목은 check_id, status, numerator, denominator, violation_fraction, unobserved_count, missing_annotation_scopes, missing_reasons와 findings를 가진다.
denominator는 실제로 필요한 주석이 갖춰져 검사한 단위 수다. numerator는 하나 이상의 구조 위반이 있는 단위 수이며 findings 행 수와 다를 수 있다. violation_fraction은 두 수의 비율이고 denominator=0이면 null이다.
관찰한 단위가 있으면 observed, 필요한 주석이 없으면 not_observable, 명시된 빈 목록이나 적용 대상이 없으면 not_applicable이다. 일부 단위만 관찰하면 관찰 분모와 미관찰 수를 함께 낸다. 목록 자체가 없어 총량을 모르면 unobserved_count=null이며 missing_annotation_scopes에 원인을 남긴다.
semantic_quality_scores=null, semantic_quality_status=not_measured와 automatic_quality_acceptance=false는 모든 결과에서 유지한다. 통과 개수나 위반 비율을 글 품질 점수로 환산하지 않는다. 본인 사실이나 문항이 참인지, 연결된 근거가 주장을 지지하는지, 계획이 현실적인지는 별도 사람 판단이다.

5. 네 품질 영역의 사람 관찰
유기성은 문장 경계, 문단 첫끝과 전체 순서를 보고 앞의 질문 받기, 보완, 대비와 목표 이동을 기록한다. 기계의 순서 위반과 ID 연결은 후보 진단이다. 대상 반복과 접속어 수에 보상을 주지 않는다.
개연성은 주장-사실-이유의 묶음에서 관련성, 기여 범위, 대안 원인과 인과 비약을 본다. fact_id가 존재하는 것과 의미 지지가 되는 것을 나눈다.
문항 적합성은 공식 명시 요구 하나와 대응 문단의 직접, 부분, 미대응을 판정한다. 사람 기준으로 완전 대응 요구/적용 요구와 필수 누락을 기록한다. 공식 문항이 없으면 일반 구성만 평가한다.
실행 가능성은 작업-자원-선행 작업-산출물-검증-축소 대안을 분야 검토자가 본다. 날짜와 순환 위반이 없다고 자원 확보와 수행 능력이 입증되지는 않는다.
실제 경험 입력의 필수 재료에 대한 사람 기준과 선택 재료를 비교해 선택 정밀도와 재현율을 산출하는 것은 후속 평가다. 현재 도구는 명시 참조와 사람 원점수 집계까지 구현했다.

6. 사람 평가 집계와 비교 경계
사람 기록은 criterion_id, unit_id, reviewer_id, reviewer_type=human, provenance=actual_human_review, review_record_id, source_ref.evidence_id와 score를 요구한다. 이는 입력 선언과 참조 확인이며 사람의 실재나 독립성을 자동 인증하지 않는다. 모델 기록과 출처 없는 기록은 제외 사유를 남긴다. 문서가 synthetic_fixture이면 가짜 사람 라벨을 붙여도 일치도를 산출하지 않는다.
동일 기준의 두 평가자만 지원한다. 조정 전 원점수를 보존한다. 동일 단위와 평가자의 중복 기록이나 세 명 이상은 임의 선택하지 않고 미측정으로 둔다. 관찰 불가와 해당 없음은 null로 기록하고 한쪽이라도 없으면 해당 쌍을 제외한다. 기준별 두 쌍 미만이거나 어느 한 평가자의 값이 상수면 κ=null이다. 상수 정책은 일부 수학적으로 계산 가능한 경우도 보수적으로 보류하는 프로젝트 규칙이다.
범주의 위치를 i,j, 범주 수를 K라 할 때 이차 불일치 가중치는 ((i-j)/(K-1))^2다. 관찰 도수 O와 주변 도수로 만든 기대 도수 E를 사용해 κ=1-sum(w*O)/sum(w*E)를 계산한다. 정확 일치율, 혼동표, 두 평가자의 분포, 평가 단위 수와 결측 제외 수를 함께 낸다. 음수 κ를 0으로 자르지 않는다. minimum_pairs=2는 산술 착수 기준이며 통계적 신뢰 보증이 아니다. α와 신뢰구간은 구현하지 않았다.
이전 30문항 제안은 본인 동의 자료 확보가 선행돼야 하는 후속안이다. 현재 사람 평가와 사용자 효과의 완료량은 0이다. 우선 동의한 소수 경험에서 독립 두 사람의 불일치를 점검하고 기준을 고친다. 교정과 평가의 작성자, 경험과 프로그램을 분리하고 생성 경로를 가린 쌍대 비교를 한다. 같은 문항, 확인 사실, 허용 참고자료와 예산을 맞추며 본 실험 전 표본과 주지표를 고정한다. 본인 사실 혼입과 공식 요구 누락은 문체 점수로 상쇄하지 않는다.

7. 합성 실행의 해석
기존 T3-traces-v3의 research-fit, execution-proposal, leadership, multi-experience-selection에서 실제 남아 있는 합성 미리보기 4개를 읽었다. 글이나 아키텍처를 다시 생성하지 않았다. 문장과 사실 ID는 보존된 추적에서 복사했으며 주체는 사실 메타데이터에서 옮겼다. 요구-역할 연결과 기대 문단 순서는 실행 담당이 넣은 합성 정답 주석이다.
각 원본에 문단 순서 뒤집기, 주체 바꾸기, 계획을 실적으로 제시하기, 명시 요구에 연결된 문장 삭제, 일정 순환의 다섯 변형을 적용한다. 주체와 계획 변형은 문장과 해당 주석을 함께 고쳤다. 순환 변형에는 원래 없던 두 노드 그래프를 수작업으로 추가했다. 따라서 텍스트에서 주체, 시제나 요구를 자동 이해한 성능이 아니다. 원래 없던 출처 구간과 일정 날짜는 미관찰로 남긴다.
원본 4개와 변형 20개의 입력, 결과, 원본 경로와 해시는 quality-execution에 분리 보존한다. expected 코드와 진단 코드를 대조한 수는 이 명시 변형 묶음의 진단 민감도이며 한국 지원서 품질, 독자 설득과 선정 효과가 아니다. 숫자 배열로 κ 공식을 확인하는 단위 검사는 사람 평가 실적으로 집계하지 않는다.

새 bridge 출력의 추가 통합은 bridge-integration/manifest.json에 별도 4건으로 기록했다. 한 과제, 완료와 진행 혼재, 기여 미확인, 단문 사례다. 기존 24건의 분모에 합치지 않는다. 문장과 사실, 명시 상태, 원문 구간과 경계 연결을 옮긴 수작업 스키마 어댑터이며 실제 글의 의미를 추론하지 않았다. 공통 원문 해시는 일치하는지 확인한 뒤 source 객체에 한 번 저장했다. 상태 접두어가 붙은 기여 문장은 원문과 문자 단위로 같다고 선언하지 않으며, 압축 입력에서 생략한 중복 value는 해시를 보존한 상류 원본과 인용에 남아 있다. 요구의 의미 대응과 실제 일정은 주석이 없어 미관찰이다. 기여 미확인 사례의 text=null과 상류 need_info를 유지한다. 진단 위반이 없다고 이 사례의 준비 완료를 판정하지 않는다.
