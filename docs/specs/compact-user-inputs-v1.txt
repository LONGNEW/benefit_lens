BenefitLens 작은 공통 조건과 사용자 질문 계약
기준: 2026-11-20

숫자의 의미
이전 보고의 공통 필드 9,012개는 필드 종류가 아니라 공고의 원문과 필드를 연결한 매핑 행 수였다. 공유 저장 필드는 현재 19종이다. 이 중 14종이 기존 사용자 정보이며, 마감과 지원 금액은 공고 자체의 정보다. 프로그램별 세부 키는 별도의 의미 분류가 필요하다.

작은 공통 표현
조건 유형은 42종을 정의했고 100종을 상한으로 둔다. 유형마다 입력 그룹과 설명을 등록한다. 알 수 없는 표현 때문에 새 필드가 자동으로 늘어나지 않는다. 문맥을 읽어 분류하기 어려운 조건은 확인 대기로 남는다.
전체 상황에 사용할 수 있는 사용자 입력 항목은 35종이며 검색 선호 두 항목을 포함한다. 상한은 100종이다. 이 목록은 모든 학생이 반드시 작성할 양식이 아니다.

첫 화면: 두 묶음, 여섯 항목
학업 기본: 소속 학교, 현재 학위 과정, 재학 상태, 전공.
찾는 기회: 희망 국가, 지원 유형.
초기 항목을 모두 필수로 요구하지 않는다. 재학증명서나 성적표를 제공하면 문서에 명시된 값만 채우고 사용자가 확인한다. 현재 박사과정이라는 이유로 학위 취득이나 coursework 수료를 추정하지 않는다.

전체 여덟 묶음
1. 학업 기본 정보: 학교, 학위 과정, 학적, 전공.
2. 찾는 기회: 국가와 지원 유형이라는 검색 선호.
3. 추가 학업 조건: 성적, 만점, 수료, 전일제, 학년과 선수과목.
4. 국적과 거주 조건: 국적, 거주, 기준일의 나이와 해당 공고의 경제 조건.
5. 활동과 근로 조건: 활동 기간, 근로 자격, 비자와 이동 조건.
6. 경험과 자격: 경력, 언어, 기술, 면허와 자격증.
7. 제출 준비: 서류와 추천, 과거 신청 이력, 중복 참여와 제출 관련 확인.
8. 공고별 특수 조건: 분류나 의미 확인이 필요한 내부 검토 항목. 포괄적인 추가 정보 질문을 자동으로 만들지 않는다.

질문을 줄이는 규칙
선택한 공고에 필요한 조건만 추가로 확인한다. 동일한 사람, 기준 시점, 단위와 의미 범위가 확인된 정보는 재사용한다. 서로 다른 시점과 단위, 재학 학위와 취득 학위는 합치지 않는다.
학점 3.0 이상과 3.5 이상은 같은 성적 입력을 재사용할 수 있지만 각 공고의 기준값은 별도로 유지한다. 질문을 묶는 작업으로 AND, OR, 제외 조건과 예외를 바꾸지 않는다.
기관이 제공하는 복지, 고용 후 담당 업무와 기관의 행정 의무는 학생의 기본 개인정보 질문으로 만들지 않는다. 우대는 선택 사항으로 남긴다. 검토되지 않은 조건과 의미 미확정 조건은 실제 질문으로 발행하지 않는다.

표현을 묶는 실제 처리
공고별 원문과 필드 매핑을 그대로 보존하고 별도의 작은 조건 유형에 연결한다. 예를 들어 학위명 표현은 학위 유형으로, 면허 표현은 면허 유형으로 묶되 국가, 면허 종류와 기준 시점은 원래 조건에 남긴다. 복지와 보험 설명은 공고 정보에 배치한다.
특수 키, 조건 주체, 문장 역할과 대표 원문을 묶어 실제 LLM으로 100개씩 분류한다. 분류 결과가 지정된 유형인지, 인용이 실제 입력 원문에 있는지 검사한다. 애매한 유형을 억지로 합치지 않고 unresolved로 남긴다. 이 분류는 실행 가능한 자격 판정이나 내용 승인을 의미하지 않는다.

구현

tools/benefitlens_profile_questions.py: 질문 묶기, 대상 공고 필터, 같은 학생의 확인 정보 재사용.
tools/build_benefitlens_profile_projection.py: 원문 매핑을 작은 유형에 연결하며 원본은 참조로 보존.
tools/run_benefitlens_requirement_types.py: 실제 원문 의미 분류와 실행 영수증, 재개 처리.
개인화 산출물의 user_input_plan을 사용자 질문에 사용한다. input_channels와 원문 매핑 행은 추적과 검토용이다.
