BenefitLens 공고 경험 작성 파이프라인 실행 명세

목적
공고의 요구 문항을 해석하고 다른 프로그램의 작성 경험에서도 적절한 구성 근거를 찾아, 지원자 사실을 사용한 초기 초안을 만든다.

입력과 저장
기존 Python 수집기와 원문 무결성 뷰에서 확보된 문서를 읽는다. source_document는 원문 경로와 해시, notice_document는 공고와 원문 판본을 연결한다. 조건은 고정된 42개 분류와 공통 또는 특수 범위, 자격 또는 제출 등 역할, 값, 단위, 논리, 근거 위치를 갖는다. 기존 연결을 새 분류에 연결한 행은 legacy_alias_only 상태로 유지한다.

의미 분석
공고 전체에서 자격, 제출, 평가, 수혜와 활동 의무를 나눈다. 작성 문항은 자격 질문과 분리하고 지역별 적용 범위를 보존한다. 경험은 전체 작성본에서 독자 질문, 핵심 주장, 재료 선택과 배치 이유, 문단의 역할과 연결을 분석한다. 인용된 위치와 전체 텍스트의 입력 전달 범위는 별도로 기록한다.

검색
공고와 경험의 표현을 같은 multilingual-e5-small 인코더로 임베딩한다. 조건 조회는 SQL 경로, 작성 자료는 문항 의도와 장르에 맞춘 벡터 경로를 사용한다. 구절은 재료나 조언 참고, 전체 문서는 구성 참고로 구분한다. 원문 관련성이 부족한 후보는 제외한다. 검색 유사도는 개인 자격 판정에 사용하지 않는다.

전략과 전술
전략은 무엇을 설득할지와 어떤 본인 경험을 선택할지 정한다. 전술은 실제 빈칸 문장과 문단 연결을 정한다. 모든 양식은 편집상 적용이며 공식 문항의 순서와 분량이 우선한다. 기관 자원과 후속 활동은 근거가 있을 때만 선택 문장으로 추가한다.

초안
개인 사실은 공개 작성자와 다른 주체로 저장한다. LLM이 슬롯 값과 근거 사실 ID를 선택하고, 유형과 시제 검사를 거쳐 문장을 조립한다. 완료 사실을 계획 슬롯에 연결하면 DB가 거부한다. 필수값이 없으면 자리표시자를 유지하고 incomplete_required_slots를 출력한다. 실제 제출본 품질과 선정 가능성은 별도 평가 대상이다.

실행
python3 tools/benefitlens_end_to_end.py all --output 새절대경로
현재 실행 결과: outputs/benefitlens/pipeline_20261120
핵심 검사: python3 -m unittest discover -s tools/tests -p test_benefitlens_end_to_end.py
원문 데이터와 모델은 /home/longnew/.cache 아래를 사용한다. 새 실행은 독립된 캐시 DB를 사용하며 입력 해시가 달라지면 이전 모델 결과를 재사용하지 않는다.
