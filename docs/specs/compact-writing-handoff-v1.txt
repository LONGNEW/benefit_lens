표현 묶음 해석과 작성 패턴 인계 v1

범위
텍스트 추출과 문장 분리는 코드가 수행한다. 관련 표현과 주변 문맥을 묶은 뒤 30~50개 묶음을 한 번의 짧은 LLM 요청으로 정리한다. 인계 도구는 보존된 묶음 해석과 원문 연결을 읽으며 모델을 호출하지 않는다. 이전 문서별 장문 평가의 큐와 원출력은 보관 자료로 참조한다.

완료 단위
LLM 해석 완료 그룹 수는 실제 호출 영수증, 그룹의 입력 지문, 보존 결과와 결과 검증이 연결된 그룹만 센다. 대기 그룹과 코드로 추출한 표현 수는 이 값에 포함하지 않는다.
실제 적용 원문 문장 수는 검증 완료 해석이 연결된 고유 원문 문장을 센다. 같은 문장에 표현이 여러 번 등장하거나 여러 그룹이 연결되어도 한 문장으로 센다. 주변 문맥 전체를 적용 문장으로 확대하지 않는다.
출처 문서 수는 적용 문장이 있는 고유 출처 문서 수다. 지원 공고, 경험 자료, 교재와 문학 조언 등은 자료 역할과 장르별로 구분한다.
대기 수는 아직 모델에 보내지 않은 그룹과 occurrence다. 미해결 수는 모델을 거쳤으나 해석을 확정하지 못한 그룹, 원문 연결 또는 적용 조건이 맞지 않는 occurrence를 각각 기록한다. 그룹과 occurrence의 미해결 사유도 나누어 집계한다.
공급자의 사용량 한도로 실행되지 않은 waiting_provider_limit는 waiting_provider_groups와 waiting_provider_occurrences로 따로 기록한다. 의미 해석 실패나 완료 수에 넣지 않는다. CLI 시도 수와 실제 모델 실행 수를 분리하고, 429 원응답과 요청 파일의 해시 및 사용 토큰을 대조한다. 자동 재시도는 인계 도구의 기능에 포함하지 않는다.

모델이 본 대표 문맥과 코드 적용 범위
배치 입력에 실제 포함된 대표 occurrence를 보존한다. 같은 해석을 여러 원문에 코드로 연결한 수와 모델이 직접 본 대표 문장의 수를 분리한다. 반복 표현의 의미가 달라지는 조건, 예외, 주체와 시점은 적용 제약으로 유지한다.

작성 구조 보존
그룹 해석에서 확인한 재료 역할, 주장과 근거 및 추론, 문장의 기능, 앞뒤 내용의 관계와 적용 한계를 보존한다. 원문의 문단 위치와 문장 순서에 연결해 부분적인 작성 전개로 제시한다. 첫 문장이나 마지막 문장이라는 위치는 코드가 확인한 원문 경계와 함께 사용한다.
선택된 문맥에서 관찰한 내용은 selected_occurrences_only 범위다. 관찰이 없는 첫 문장 기능, 결말, 다음 문단 연결이나 문서 전체 논리를 채우지 않는다. 실제 요구와 공식 안내, 사례에서 관찰한 전략, 우리가 제안하는 전이를 구분한다.
한 사례에서 얻은 전개는 single_case_observation으로 남긴다. 여러 표현이 같은 그룹이라는 사실을 공통 성공 패턴이나 합격 효과로 해석하지 않는다. 출처 인물의 사실을 사용자 사실로 복사하지 않는다.

내용 검토
writing_evidence_framework_v2의 요구 → 주장 → 근거 → 추론 → 문단 → 문서 연결을 참조한다. 짧은 그룹 해석은 이 연결에 사용할 근거 조각이며 완성 지원서의 논리 검토와 구분한다. 일반 원칙, 장르 조건과 사용자 스타일 선호를 따로 보존한다.

재사용
새 원문에서 기존 그룹과 동일한 의미 조건이 확인되면 해석을 재사용하고 새 occurrence만 연결한다. 의미나 적용 조건이 달라지면 미해결로 남겨 다음 소규모 배치에 포함한다. 같은 입력 지문의 모델 결과를 다시 요청하지 않는다.

실행과 출력
도구: tools/build_benefitlens_compact_handoff.py
실행: python3 tools/build_benefitlens_compact_handoff.py
입력: 공용 캐시 team-production-20261119/compact/queue.sqlite
출력: 같은 compact 루트의 handoff 디렉터리
summary.json은 자료 종류별 완료 그룹, 관련 또는 무관 판정, 실제 연결 문장, 대표 문장, 출처 문서, 대기와 미해결을 제시한다. 고유 문장은 document_id, text_sha256, sentence_index로 중복 제거하고 원문 표현 span 수와 분리한다.
group-interpretations.jsonl은 짧은 해석과 호출 근거, applied-occurrences.jsonl은 코드 적용 원문 연결, writing-fragments.jsonl은 부분 작성 구조, unresolved-groups.jsonl은 대기와 미해결 상태를 보존한다.
영수증의 요청, CLI 원응답과 배치 결과 파일 해시, 실제 모델 사용 기록, 그룹별 결과 해시와 원응답의 의미 필드를 대조한다. 검토 후 붙은 메타데이터는 실제 모델 원출력과 분리한다.
provider=codex_subagent는 에이전트 이름, 실제 완료 메시지 artifact, 요청 지문과 원결과 해시를 대조한다. 보존 요청의 원문 binding validator도 재실행한다. completed_codex_subagent_batches는 에이전트 배치 수다. 독립적인 사용량 텔레메트리가 없으므로 내부 모델 API 호출 수, 모델명과 토큰 수는 null로 기록한다. Claude CLI 시도와 429 기록은 별도 보존한다.
provider=codex_cli는 실제 stdin, exec --json의 JSONL 이벤트, 마지막 turn.completed의 usage, 최종 agent_message와 응답 파일, raw 및 validated 그룹 포인터를 대조한다. usage_events는 관측 원문으로 보존하고 내부 API 호출 횟수나 모델명을 추정하지 않는다. 세 provider의 배치와 사용량 근거는 분리한다.
검사: python3 -m pytest -q tools/tests/test_benefitlens_compact_handoff.py
합성 fixture의 검사는 실제 모델 분석이나 글쓰기 품질 평가 건수에 포함하지 않는다.
