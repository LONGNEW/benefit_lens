공고 조건과 공유 SQL 연결 v1
기준일: 2026-11-20

도구
python3 tools/link_benefitlens_condition_schema.py --base <team-production-20261119>
조정기가 compact/handoff/.refresh.lock을 이미 보유하면 --artifact-lock-fd FD와 pass_fds로 같은 파일 기술자를 전달한다.

입력
compact/queue.sqlite의 실제 analyzed 공고 그룹과 발생 위치를 읽는다. 모델 호출 영수증, 요청, 원응답, 완료 기록과 검증 결과의 해시를 재확인한다. analyzed 상태만 가진 그룹은 완료 수에 넣지 않는다.
team-expansion-20261120/experience-personalization/personalization/requirements.sqlite와 summary.json을 읽는다. 공고 원문 참조는 notice/notices.jsonl.gz, 공유 필드는 pipeline/config/shared_condition_catalog_v1.json을 따른다.
개인화 summary의 매핑 수, 공고 수와 catalog 해시가 입력 DB와 다르면 실패하고 이전 산출물을 유지한다. 실행 중 늘어난 공고 분석 그룹은 projection lag로 기록한다.

검증 경로
그룹의 실제 모델 응답 → 원문 발생 위치 → 결정적으로 생성한 mapping_id → catalog field_id → 해당 공고의 requirements.input_channels 안의 동일 mapping_id와 route를 연결한다.
매핑의 evidence_quote, value_quote와 논리 단서는 원문의 정확한 문자 위치로 다시 결속한다. 다른 문서에 재사용한 문맥은 그 문서의 오프셋으로 검증한다. subject, modality, statement_type과 reference_phase를 보존한다.

출력
team-expansion-20261120/semantic-connections/conditions/summary.json
team-expansion-20261120/semantic-connections/conditions/conditions.sqlite

SQLite의 condition_schema_links 뷰가 group_id, mapping_id, field_id, field_scope, requirement_route, 원문 버전과 실행 영수증을 제공한다. source_bindings에는 실제 인용과 문자 위치를 남긴다. analyzed_groups, candidate_sources, occurrences, mappings, catalog_fields와 requirement_routes의 FK를 검사한다. unresolved는 검증에 실패한 그룹과 매핑의 이유를 보존한다.

집계
counts.actual_llm_analyzed_distinct_notice_groups는 영수증이 검증된 실제 분석 그룹 수다. 그중 mappings가 있는 그룹은 actual_llm_relevant_distinct_notice_groups로 센다.
counts.verified_relevant_mapping_instances와 source_schema_link_complete_mapping_instances는 원문, 모델 출력, 공유 필드와 개인화 경로가 모두 연결된 매핑 수다. verified_linked_unique_candidate_notices는 그 매핑을 가진 중복 없는 공고 후보 수이며 공고 전체의 해석 완료 수로 사용하지 않는다.
공통 필드와 program_specific.requirement는 각각 common_field_mapping_instances와 program_specific_mapping_instances로 나눈다. 프로그램별 조건 문자열을 서로 같은 전역 필드로 합치지 않는다.
source_verified_question_route_links는 common_profile, program_followup과 optional_followup의 신청자 질문 후보 경로 수다. 실제 질문 발행 수는 0이다. 기관과 프로그램 정보 경로를 포함한 전체 수는 by_requirement_route를 따른다.
content_approved_canonical_rules는 0이다. 모든 연결은 semantic_review=unreviewed, executable=0, canonical_rule_id=null을 유지한다. 값 추출 방법은 실행하지 않으며 현재 접수 여부와 개인 자격을 새로 판정하지 않는다.

증분과 동시 실행
실행마다 영수증과 원문을 다시 해시한다. 입력과 코드 지문이 같은 기존 그룹 및 매핑의 검증 결과를 재사용한다. 원본 SQLite는 query_only 읽기 트랜잭션으로 연다.
공유 artifact lock, 개인화 campaign.lock과 출력 lock을 보유하고 실행한다. 잠금이 사용 중이면 종료 코드 75로 끝난다. dependency 오류는 종료 코드 1이며 이전 완료 세대를 유지한다.
새 세대는 임시 디렉터리에 SQLite와 summary를 완성한 뒤 current 심볼릭 링크를 원자적으로 바꾼다. 여러 파일을 읽는 외부 소비자는 먼저 current의 실제 세대 경로를 고정하거나 summary에 기록된 DB 해시를 대조한다. 완료 세대는 자동 삭제하지 않는다.
