# BenefitLens 성적·어학 축소 데모: 설계와 검증 제안

문서 표기일: 2026-10-04. 상태: **설계 초안**. 팀의 확정 결정이나 구현·실행 완료 보고가 아니다. 기존 70건 분석은 2026-10-03 UTC에 저장 자료를 읽기 전용으로 확인한 결과다. 실제 학생 자격·선발·지급을 확정하지 않는다.

Team 4의 주제는 학생 맞춤 지원 탐색과 신청서 초안 지원을 위한 데이터 파이프라인이다. 제안 발표는 10월 20일/22일 중이며 팀별 일정은 미확인이다. 제안 범위는 아이디어·수집/전처리·DB 관리, 완제품은 기말 목표다. 이번에는 **공고 원문 → 성적·어학 조건 후보 → 근거를 가진 타입 규칙 → 합성 학생 비교 → 초안 수정**을 작은 범위로 시연하는 안을 제안한다.

## 1. 확인된 자료와 선택 이유

기존 D1의 70행은 **공고 17행 + 정책 항목 53행**이다. 기본 출처 URL은 공고 17개·정책 페이지 11개로 총28개다. 같은 정책 페이지에서 여러 제도를 분리한 것이므로 53행을 53개 독립 모집으로 보거나 URL로 합쳐 삭제하면 안 된다. 같은 제목이라도 학과·지원액·조건이 다를 수 있다. 고유 사업·모집 회차·정책 가족 수는 현재 확정하지 못했다.

모든 행은 `needs_review`다. 숫자 타입 AST는 **14 leaf/12행**에 있지만 나이·남은 수업연한·학년·대학원 학기·팀 인원에 한정된다. GPA·백분위·이수학점·지원구간이 텍스트에 있어도 숫자 규칙으로 정규화되지 않은 사례가 있다. `structured_rule_count` 합194와 실제 AST207의 불일치도 있어 저장 메타 카운트를 승인 지표로 쓰지 않는다.

`institution=54/70`과 `department=26`은 주로 수집기가 넣은 POSTECH/학과 범위다. 두 공고의 내일배움카드 나이·수업연한도 같은 공통 규정의 재사용이다. 이를 독립 공고에서 자주 요구되는 조건이라고 해석하지 않는다. 생성 label, 날짜·주소·전화번호·목차 숫자, presentation 섹션 및 이전/다음 게시글 혼입 가능성을 원문 조건과 구분한다.

| 첫 데모 관련 관찰 | 저장 AST | 저장 텍스트 후보 | 해석 한계 |
|---|---:|---:|---|
| GPA | 0 | 명시2행 + 척도 없는 괄호 숫자2행 | 괄호 `(3.0)/(2.0)`에 만점·환산을 임의 부여하지 않음 |
| 백분위 | 0 | 3행 | GPA와 별도 지표로 비교 |
| 절대 이수학점 | 0 | 정책5행/2URL | 이번 비교 범위 밖, 근거는 보존 |
| 졸업학점 대비 비율 | 0 | 공고1행의40% | 절대학점과 다르고 이번 비교 범위 밖 |
| 영어시험 종류·점수·응시일·유효기간 | 0 | 공고1행의 TOEFL 선택서류 언급 | 최소점수·유효기간 규칙을 확보했다는 뜻이 아님 |

영어 후보는 포스코 해외유학 공고의 **선택 제출** 어학성적(TOEFL 등)과 기타 시험성적(GRE 등) 증빙 문구다. 이를 영어 최소점수의 필수조건으로 승격하지 않는다. GRE를 영어시험 점수에 합치지 않는다. 이 관찰은 D1 저장 문구 분석이며 원문·첨부 전수 확인 결과는 아니다.

세부 근거와 분모는 [숫자·중복 분석 문서](academic_demo/numeric_inventory_dedup.md), [행별 집계 JSON](academic_demo/numeric_inventory_dedup.json)에 있다. 기존70건에서 영어 수치·유효기간 조건을 갖춘 실제 검증 표본이 이미 확보됐다고 주장하지 않는다. 첫 시연용 공고는 같은 판본의 본문·첨부를 확인한 뒤 별도로 선택한다.

## 2. 첫 데모에서 비교할 것

비교 대상은 성적 최저기준과 영어시험 최저기준이다. 성적의 종류·척도·기간이 맞는지, 같은 영어 성적표가 시험종류·점수·날짜 조건을 함께 만족하는지부터 보여준다. 성적 향상도·상대순위·선발 배점·다른 시험으로의 점수 환산은 최소 데모의 자동 비교에 넣지 않는다.

재학/수료, 학년·학기수, 이수학점, 거주, 지원구간, 소득, 국적, 중복 장학금, 서류, 선발·지급 등 원문에 있는 다른 조건은 버리지 않는다. 조건 역할과 원문 근거를 보존하되 결과는 `not_evaluated`로 둔다. 사용자가 값을 입력해도 이번 범위에서 계산하지 않는다는 의미다. `unknown`은 비교 대상인데 필요한 값·척도·기준일·승인 근거가 부족하다는 의미이며 두 상태를 구분한다.

| 상태 | 의미 | 화면 표현 제안 |
|---|---|---|
| `pass` | 승인된 성적/어학 조건이 비교 가능한 사실과 일치 | 해당 조건 일치 |
| `fail` | 같은 종류·척도·기간에서 명시된 문턱 미달 | 해당 조건 불일치 |
| `unknown` | 값·종류·척도·기간·원문 해석 또는 규칙 승인이 부족 | 확인 필요 + 부족한 항목 |
| `not_evaluated` | 이번 비교 범위 밖 | 비교하지 않음 + 원문 근거 |

범위 안의 조건이 모두 `pass`여도 전체 신청 자격은 **미평가**다. 결과 카드에 ‘성적·어학 조건 비교’와 ‘다른 필수조건 미평가’를 함께 표시한다. 선정 가능성이나 수혜 확률로 바꾸지 않는다. 다른 조건에서 알려진 제외가 보이면 근거를 안내할 수 있지만 이 데모가 그 조건을 판정했다고 표시하지 않는다.

원문이 조건을 요구하지 않는 경우, 선택서류만 있는 경우, 추출하지 못한 경우도 구분한다. 승인된 완독 근거가 없는 공백은 ‘조건 없음’으로 채우지 않는다.

## 3. 최소 정보 규격

다음은 구현 상태를 설명하는 스키마가 아니라 수집·저장·비교를 연결할 **제안 규격**이다.

| 객체 | 핵심 필드 | 보존 목적 |
|---|---|---|
| 공고/게시본 | `notice_id`, 운영기관, 사업명, 회차, 게시 URL | 수집 게시처와 운영기관 분리; 미확정 회차는 미상 |
| 원문 판본 | `source_version_id`, URL, 수집시각, 파일 SHA256, 원문파일, 게시/적용연도·학기 | 규칙을 특정 판본에 고정, 개정 이전 판본 보존 |
| 규칙 근거 | `evidence_id`, 판본ID, PDF쪽/표행/HTML영역, 인용, 확인상태 | label이나 요약을 원문 인용과 혼동하지 않음 |
| 조건 | `rule_id`, 역할, 타입 field, 연산자, 값·단위, 기간/기준일, AND/OR 그룹, 근거ID, 검토상태 | 필수·제외·예외·선택서류 구분 |
| 학생 관측값 | `fact_id`, 값·척도·기간, 시험/성적표ID, 확인상태 | 사실이 없으면 미상; 데모는 합성 입력 |
| 비교 기록 | 적용 규칙판본, 관측값ID, 평가시각, field별 상태·이유, 범위 밖 조건 | 같은 입력과 같은 판본의 재현 |

### 성적

- `metric`: `gpa` 또는 `percentile`. GPA와 백분위를 다른 축으로 보존한다.
- `value`, `scale_max/scale_id`, `operator`, `threshold`: GPA 만점은 비교에 필수다. 원문에 없는 만점·환산표를 만들지 않는다.
- `aggregation_basis`: 누적·직전학기·지정 학기 구간의 종합평균 등. `period`에는 대상 학기 또는 시작/끝과 원문 표현을 보존한다.
- `context`: 학위 과정, 평가 시점, 교환학기 대체 같은 적용 문맥. 문맥이 미상인 값을 다른 규칙에 끼워 맞추지 않는다.
- 여러 학기 평균의 산식이 미명시라면 임의로 계산하지 않는다. 공식 성적표의 해당 집계값을 확인하거나 `unknown`으로 둔다.

### 영어시험

- `exam_type`, `exam_variant`, `score_metric`: 예를 들어 TOEIC L/R과 Speaking을 같은 시험으로 합치지 않는다. TOEFL의 시험 버전·점수 체계도 보존한다.
- `score_value`, `score_scale/scale_version`, 최저점수 연산자: 다른 시험으로 임의 환산하지 않는다. 등급형 시험은 순서가 승인된 척도가 없으면 최소 숫자 비교에 넣지 않는다.
- `test_date`, 필요하면 성적표의 `valid_until`, `exam_result_id`: 점수와 날짜는 **같은 응시 결과**에 묶는다. 높은 점수는 첫 응시에서, 최근 날짜는 다른 응시에서 가져와 결합하지 않는다.
- `date_rule`: 응시일 하한/상한 또는 유효기간, 기준일(신청일·마감일·공고일 등), 적용연도·학기, 경계 포함 여부, 날짜 정밀도·시간대. 원문이 요구하는 것만 비교한다.
- 원문이 ‘2년’이라고 하면 승인된 기준일을 기준으로 달력 연산을 한다. 일괄730일이나 모든 시험에 공통2년을 적용하지 않는다. 기준일/경계가 불명확하면 `unknown`이다.

### 버전

`schema_version`(정보 구조), `source_version_id`(공고 판본), `rule_version`(검토된 조건), 척도/제도 버전, 적용연도·학기를 구분한다. 스키마가 같아도 조건값과 적용기간이 달라질 수 있고, 같은 숫자 표기라도 제도 버전이 다르면 뜻이 달라질 수 있다.

[한국장학재단 학자금 지원구간 안내](https://www.kosaf.go.kr/ko/tuition.do?pg=tuition04_09_07)의 **2027년1학기 지원구간 개편 안내**는 적용연도·제도 버전을 함께 보존해야 하는 사례다. 공식 본문 확인 기록은 [제도 버전 참고](academic_demo/kosaf-2027-version-reference.json)에 보존했고 이 문서에서 세부 개편표나 변환 규칙을 복제하지 않는다. 지원구간은 이번 자동 비교 범위 밖으로 보존한다.

## 4. AND/OR와 예외

시험 대체 경로를 OR로 묶고, 각 경로 안에서는 같은 성적표의 조건을 AND로 묶는다. 성적도 원문이 제시한 GPA 만점별 기준·백분위 기준의 대체 관계를 그대로 보존한다.

```text
성적 그룹 = OR(원문 GPA척도A 경로, 원문 GPA척도B 경로, 원문 백분위 경로)
각 성적 경로 = metric + 척도 + 집계기간/문맥 일치 AND 최저기준 비교

영어 그룹 = OR(시험A 경로, 시험B 경로, ...)
각 영어 경로 = 시험종류/버전 일치 AND 같은 응시결과 점수 비교
               AND 원문이 요구한 응시일/유효기간 비교

범위 안 결과 = 원문의 성적·영어 관계에 따른 AND 또는 OR
전체 자격 = 미평가 (다른 필수조건 not_evaluated)
```

위 식은 형태 예시이며 모든 공고에 두 그룹을 필수 AND로 강제하지 않는다. 원문의 ‘또는/모두/해당자만’을 승인한 그룹으로 저장한다. 예외가 특정 경로에만 적용되면 그 경로 안에 둔다. 승인되지 않은 조건이나 미해결 예외를 삭제해 통과시키지 않는다.

AND는 하나라도 `fail`이면 실패, 전부 `pass`이면 통과, 그 외는 미상이다. OR는 하나라도 `pass`이면 통과, 모든 대체 경로가 `fail`이면 실패, 그 외는 미상이다. 범위 밖 `not_evaluated`를 참 값으로 바꾸지 않으며 선택한 범위의 결과와 전체 자격을 별도로 저장한다.

## 5. 수집과 조회의 역할

원문과 첨부를 먼저 보존하고 LLM은 조건 후보·근거 위치·미해결 문구의 추출을 보조한다. 구조화 가능한 후보와 원문 숫자 출현을 구별하고, 원문 문맥·척도·기간·조건 역할·판본을 검토한 규칙만 시연의 조회 입력으로 사용한다. LLM label과 generated scope는 원문 인용으로 제시하지 않는다.

조회는 타입 있는 사실과 고정된 조건을 비교한다. 조회할 때 새로운 문턱을 만들거나 자연어로 자격을 추정하지 않는다. 누락은 이유가 있는 `unknown`, 범위 밖은 근거가 남은 `not_evaluated`로 반환한다. 규칙은 최신값 덮어쓰기보다 판본을 추가하고 해당 적용연도·학기의 규칙을 선택한다.

## 6. 신청서 초안과 사용자 표현

비교 결과가 `fail/unknown/not_evaluated`여도 **초안 또는 작성 틀을 항상 제공**한다. 자료가 없는 경우 `[본인 경험 입력]`, `[활동 기간 확인]`처럼 빈칸을 사용한다. 성적·어학 점수·경험·수상·지원 자격을 만들어 쓰지 않는다.

초안은 공고의 질문과 글자수/제출 형식, 사용자가 제공한 사실과 수정 의도를 따라 만든다. 근거가 확인된 개인정보·사실만 사용하고, 사용자가 자신의 표현으로 수정할 수 있는 편집 흐름을 둔다. 빈칸·근거가 부족한 문장·선택서류 언급은 사용자에게 드러나야 한다.

짧은 안내는 ‘AI가 만든 초안입니다. 사실과 기관의 작성 규정을 확인하고 본인의 표현으로 수정해 주세요’로 제안한다. 원문에 AI·대필 제한이 확인되면 해당 근거를 표시하고 사용자가 직접 작성할 구성안·빈칸 형태로 제공한다. 문장 생성 성공을 제출 허용이나 자격 승인으로 표현하지 않는다.

## 7. 작은 시연과 검증 계획

원문 같은 판본의 성적·영어 조건과 다른 필수조건 목록을 먼저 보여준다. 합성 학생의 성적·시험 자료를 넣고, 숫자 한 개 또는 응시일 하나를 바꿔 결과와 근거가 어떻게 변하는지 시연한다. 마지막으로 미평가 조건을 보며 초안을 자신의 표현으로 수정한다.

| 검증 사례 | 기대 관찰 |
|---|---|
| 최저점수 바로 아래/정확히 문턱/바로 위 | 원문 경계 연산자가 재현됨 |
| GPA 값은 같고 만점만 변경·삭제 | 임의 환산 없이 다른 경로 비교 또는 확인 필요 |
| 직전학기 조건에 누적 성적, 지정기간 불일치 | 같은 숫자여도 확인 필요 |
| 백분위 경로 통과·GPA 경로 미상 | 원문 OR에서 통과, 미상 경로는 기록 유지 |
| 같은 영어 점수의 유효한 응시일/경계/기간 밖 | 승인된 날짜 기준과 경계대로 비교 |
| 다른 응시 결과의 점수와 날짜를 결합 시도 | 합성된 가짜 성적표로 통과하지 않음 |
| 시험 대체 OR 한 경로 통과/모두 실패/일부 미상 | OR의 세 상태 논리가 재현됨 |
| 점수 미상·다른 조건 미평가 | 초안/작성 틀은 제공, 전체 자격은 미평가 |
| 원문 개정·척도 또는 적용학기 변경 | 이전 판본 결과 보존, 판본 혼합 금지 |

영어 필수점수 표본이 승인되기 전에는 합성 조건을 실공고라고 표시하지 않는다. 과거 모집 공고는 과거 판본 시연으로 표시하고 현재 신청 가능한 공고와 구분한다. 기존 검증자료를 보존하면서 이번 범위의 조건과 근거를 선택한다.

이번 세션의 실제 구현 파일과 실행한 검증 결과는 [구현·실행 기록](academic_demo/implementation-report.md)에 별도로 기록한다. 설계 제안과 검증한 구현 범위를 구분한다. 배포·외부 공유·유료 실행·실사용 DB 변경·실제 학생의 자격 판정은 이 제안 작업의 결과가 아니다.
