## 현재 범위와 목적

BenefitLens의 현재 제안 범위는 POSTECH 재학생이 학교, 재단, 기업과 국가의 등록된 공식 출처에서 금전적 지원 기회를 검토하고, 선택한 공고의 실제 문항에 맞춰 자기 경험으로 첫 초안을 만드는 것이다. 장학금은 범용 지원 준비 구조를 검증하는 첫 도메인이다. 연구실, 취업과 공모전으로 넓히는 것은 별도 범위 변경이며, 개인정보를 받았다고 자동으로 자격을 확정하거나 합격을 예측하지 않는다.

사용자가 보아야 할 결과는 기회 목록만이 아니다. 해당 공고가 왜 표시됐는지, 어떤 조건이 충족 또는 미확인인지, 문항별로 어떤 경험이 더 필요한지, 초안의 주장이 어느 사용자 답변에 근거하는지 보여준다.

## 두 파이프라인

```text
A. 등록 공식 출처 → 수집 실행과 원본 → 변경 문서 식별
   → 공고 버전과 자격 조건 정규화 → 근거 검증
   → 동의받은 프로필 스냅샷과 대조 → 조건별 판정

B. 선택한 공고 버전 → 공식 문항과 평가 기준 정규화
   → 이용 허용 자료의 구조 패턴 → 사용자 경험 질문
   → 답변 확인 → 신규 개요와 초안 → 주장 계보 및 누락 검사
```

현재 구현은 `platform.data_source`, `collection_run`, `raw_document`, `document_version`과 `benefitlens.opportunity_version`, 조건, 혜택, 서류, 문항을 연결한다. 프로필 비교와 초안 편집은 브라우저에서 처리한다. 정확한 구현 필드는 [데이터 추출 계약](데이터_추출_계약.md)이 정본이며 [내부 DB 초안](../proposal/09_내부_DB와_파이프라인_기틀_초안.md)의 템플릿, 주장 계보와 개인 판정 저장은 목표 구조다.

## 어디까지 수집하고 어떻게 초안에 쓰는가

| 정보 | 수집 또는 사용 기준 | 초안에서의 역할 |
|---|---|---|
| 공식 공고, 신청 양식, 평가 기준 | 등록된 공식 출처의 버전과 근거 위치 확인 | 자격 판단과 문항 충족 기준 |
| 이용 허용된 수상 수기와 사례 | 분석 허용 범위를 출처별 확인 | 문장 복제가 아닌 서술 역할과 구조 패턴 |
| 권리 불명확한 공개 후기와 팁 | URL과 메타데이터만 보존 | 사용자에게 원문 링크 안내, 생성 입력에서 제외 |
| 사용자 경험 | 동의받아 필요한 항목만 입력, 초안 주장별 확인 상태 기록 | 개인적 사실과 선택의 근거 |

유료 자료, 인증을 요구하는 커뮤니티, 이용 조건이 불명확한 전문은 수집 및 생성 대상에서 제외한다. 권리 감사를 통과한 작성 사례가 5건 미만이면 사례 패턴 집계를 중단하고 공식 양식과 기준만으로 질문 및 점검표를 만든다. 세부 기준은 [출처와 권리 정책](../proposal/04_데이터_출처와_권리_정책.md)이 우선한다.

초안의 흐름은 `확인된 공식 요구 → 사용자 경험 사실 → 사실에서 나온 해석 → 사용자가 선택한 구성 → 새로 쓴 초안`이다. 외부 사례의 아이디어를 참고해도 표현을 바꿔 복제하지 않는다. 각 주장에는 출처나 사용자 답변, 확인 상태를 연결한다. `사용자가 말했다`는 사실 검증이 아니므로 제출 전 본인이 확인해야 한다. 정보가 모자라면 꾸며 쓰지 않고 추가 질문을 돌려준다.

## 화면과 평가

- 기회 카드에는 출처, 공고 버전, 접수 기간, 조건별 충족 및 미확인 상태와 최근 검증 시각을 표시한다.
- 초안 화면에는 문항 버전, 경험 질문, 주장별 근거, 누락 요구사항과 사용자 최종 확인 상태를 표시한다.
- 평가는 등록 출처의 커버리지, 필드 완전성, 조건 판정의 재현율과 정확도, 주장 계보 연결률, 무근거 또는 원문 재현 문장의 비율로 한다.

## 현재 상태와 다음 단계

[브라우저 화면](../web/app/benefitlens/page.tsx)은 D1 후보를 검색하고, 조건 비교 뒤 선택한 공고 버전의 문항별 준비 화면으로 연결한다. 승인 전 일치는 조건 일치 후보로 표시한다. 10월 6일 후보 73건을 연결했고 FAQ와 서류 안내의 문항 오탐을 제거했다. 현재 메인 공식 문항은 없어 일반 준비 질문을 사용한다. 별도 `/academic` 데모 문항 자료는 유지한다. 프로필과 초안 입력은 브라우저에서만 처리하고 LLM 생성은 미연결이다.

추출 후보의 정본 승격과 검토 CLI는 구현했고 실제 DB 트랜잭션에서 검증 후 테스트 변경을 롤백했다. 실제 공고 검토, 권리 승인, 미활성 출처 확장과 수집 예약은 남아 있다. 최신 구현과 실행 결과는 [복구 보고](../../../../tmp/2026-10-06-benefitlens-recovery-report.md)를 따른다.

구현 중 판단 기준은 [BenefitLens 실행 기준](실행_기준.md) 한 문서로 관리한다. 실제 후보 출처와 공개 호출 경로는 [반복 수집 출처 조사](2026-09-29_반복_수집_출처_조사.md)를 참고한다.

2026년 9월 29일 기준 실제 모집 상태와 추출 품질은 [10개 출처 전수 점검](2026-09-29_10개_출처_전수_점검.md)에 정리했다.

자유문 조건을 공통 필드로 바꾸고 통과를 계산하는 기준은 [통합 자격 판정 기준](통합_자격_판정_기준.md)을 따른다.

혜택, 자격 조건, 근거, 필요 서류와 지원 문항이 원본에서 DB로 들어가는 방식은 [데이터 추출 계약](데이터_추출_계약.md)에 정리했다.

범위를 넓혀 근거에서 새로운 기획 초안을 만드는 생각은 [확장 구상](확장_구상.md)에 별도로 보존했다. 이는 현재 합의된 구현 범위가 아니다.

출처 계층 분리의 첫 구현은 [2026-09-23 결과](Results/2026-09-23.md), 포항과 국가 예시 추가는 [2026-09-24 결과](Results/2026-09-24.md)에 기록했다.
