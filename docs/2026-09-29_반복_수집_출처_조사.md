# BenefitLens 반복 수집 출처 조사

조사일: 2026-09-29

## 결론

크롤링 중심으로 지속 수집할 출처는 충분하다. 기존처럼 사업 소개 페이지 한 건을 고정해서 읽는 방식은 버리고, 새 공고가 누적되는 목록과 그 목록이 호출하는 공개 응답을 수집해야 한다.

우선 구현할 조합은 POSTECH CSE 장학 게시판, 포스코청암재단 공지, 미래에셋박현주재단 공지, 일주학술문화재단 공지, 삼성꿈장학재단 장학공지, 한국장학재단 공지다. 이 조합만으로도 학교, 민간 재단, 기업 연계, 국가 영역의 신규 공고 탐지 파이프라인을 보여줄 수 있다.

## 기술적으로 확인한 공개 호출 경로

다음 경로는 인증 우회 없이 각 사이트 화면이 실제로 사용하는 공개 요청이다.

```text
POST https://www.sdream.or.kr/portal/information/news
body: bbsDivCd=BBSDC01&pageNo=1
response: totalCnt, pageInfo, list, BBS_SID, BBS_TITLE, REG_DT_TM

GET https://foundation.miraeasset.com/ko/news/notice/list.ajax
query: firstIndex, listCnt, pageIndex, ctgry, q
response: 공지 카드 HTML 조각, detailsKey, 제목, 날짜, 전체 건수

GET https://skhappiness.org/wp-json/wp/v2/search
query: search, per_page, page
response: 게시물 ID, 제목, URL, 상세 API 링크
```

삼성과 미래에셋 경로는 문서화된 공식 API가 아니라 공개 웹 화면의 내부 호출이다. 따라서 API로 홍보하지 않고 크롤러 구현 세부사항으로 취급하며, 응답 형식이 바뀌면 HTML 목록으로 돌아가는 대체 경로를 둔다.

## POSTECH 범위의 현실적인 처리

POSTECH 공식 장학 안내는 교외장학 공개선발 공고를 POVIS 장학 게시판에서 확인하라고 명시한다. 이 게시판은 로그인 영역이므로 인증을 우회하지 않는다. 공개 수집은 CSE 장학 게시판을 대표 피드로 사용하고, POSTECH 장학금 종류 페이지는 기회 발견이 아니라 교내 제도 기준을 보강하는 참조 데이터로만 둔다.

이 때문에 학교 출처의 커버리지는 `부분`으로 표시해야 한다. 향후 학생지원팀이 공개 피드나 데이터 제공을 허용하면 전교 범위로 승격한다.

## 구현 순서

1. 기존 포스코 사업 소개, 삼성 사업 소개, SK 단일 2026년 글 파서를 목록형 파서로 교체한다.
2. POSTECH CSE, 포스코, 미래에셋, 일주, 삼성, 한국장학재단의 목록 수집기를 만든다.
3. 목록에서는 제공기관, 게시물 식별자, 제목, 게시일, 상세 URL만 먼저 저장한다.
4. 신규 또는 변경된 항목만 상세 페이지를 수집해 접수 기간, 대상, 학력, 전공, 학점, 소득, 지원액, 제출서류를 정규화한다.
5. 제목 필터가 아니라 상세 자격 조건으로 POSTECH 학생 관련성을 계산한다.
6. 한국장학재단 월간 CSV는 초기 후보 사전으로 적재하고, 실제 접수 상태는 원문 상세 페이지로 재확인한다.

## 운영 원칙

- 하루 1회 목록 수집으로 시작하고 동일 출처 요청 사이에 지연을 둔다.
- 원문 전체 재배포보다 메타데이터, 추출된 자격 조건, 원문 링크를 저장한다.
- 원본 응답 해시와 수집 시각을 남기고 같은 게시물의 수정 이력을 보존한다.
- 목록에서 사라졌다고 즉시 삭제하지 않고 마감 또는 비활성 상태로 전환한다.
- 로그인, 캡차, 접근 제한을 우회하지 않는다.
